# Свой терминал и работа с агентами

Разбор задачи «взять окно терминала под свой контроль вместо библиотечного, заменить tmux
на mosh и сделать работу с агентами удобной» — с вердиктом по каждому вопросу и дорожной
картой из девяти этапов.

Написано 12.09.2026. Код в этот заход не менялся: поставка — разбор, решения и план;
реализация идёт следующими заходами по этапам дорожной карты.

Архитектурные решения зафиксированы в [docs/adr/](adr/) и здесь только названы номерами —
разбор каждого, включая отвергнутые варианты и полные правила, живёт в самом ADR:

| ADR | Решение |
|---|---|
| 0013 | ядро xterm.js остаётся, своей становится обвязка |
| 0014 | `tmux -CC` (control mode) вместо `tmux attach`, с откатом |
| 0015 | mosh как замена tmux отвергнут, берутся три идеи протокола |
| 0016 | история терминала живёт на клиенте, с лимитом и без шифрования |
| 0017 | рамка ввода агента скрывается визуально и обратимо |
| 0018 | совместимость протокола через объявление возможностей |

---

## Откуда задача

С телефона идёт настоящая работа: агенты крутятся в tmux на Mac, а человек отвечает им из
метро, с дивана, из очереди. В этой работе мешает пять вещей.

- **Историю не пролистать.** Пока агент печатал десять минут, всё интересное ушло вверх, и
  достать его можно только пока есть связь: каждый шаг прокрутки — запрос в copy-mode tmux
  по сети. В офлайне не листается ничего.
- **Всё тормозит.** Набранный символ едет до Mac и обратно, прокрутка дёргается, между
  тапом по сессии и картинкой — пустой экран, а после смены Wi-Fi на LTE соединение
  поднимается заново и экран перерисовывается целиком.
- **Полос ввода две.** Claude рисует свою рамку внизу, TermHub умеет показать свою, и обе
  занимают место на маленьком экране. Сверху — статусная строка tmux, которая на телефоне
  не нужна вовсе.
- **С агентами неудобно.** На вопрос «1. Yes 2. No» приходится целиться стрелками, на
  дашборде видно только значок, длинный промпт набирается вслепую, а уведомление приходит
  без текста.
- **И общий вопрос:** не пора ли взять терминал под свой контроль и не заменить ли tmux на
  mosh.

**«вdt» из задачи** — веб-клиент TermHub, PWA в `packages/web`, где сейчас живёт терминал
на xterm.js. Чтение подтверждено на брифинге, возражений не было.

---

## Что измерено

Весь разбор опирается на эти числа, а не на предположения. Проба гоняла tmux на
изолированном сокете через `node-pty` — в той же среде, в которой работает агент TermHub.

**tmux 3.7b, 12.09.2026.** Прочие версии на машине: Claude Code 2.1.269, Codex CLI
0.153.4, xterm.js 6.0.0, Node 22.

| Что проверено | Результат |
|---|---|
| Первые байты `tmux attach` | `ESC[?1049h` — alt-screen сразу и до detach |
| Первые байты `tmux -CC attach` | alt-screen не приходит вообще |
| Протокол control mode | строчный: `%begin/%end`, `%output`, `%layout-change` |
| Статусная строка tmux в control mode | клиенту не приходит: UI рисует клиент |
| Стоимость подключения в control mode | десятки байт, перерисовки экрана нет |
| Ввод байтов из control mode | `send-keys -t <сессия> -H <hex>` — работает |
| Размер окна из control mode | `refresh-client -C 100x30`, держится после ухода клиента |
| История панели | `capture-pane -p -e -S -` отдаёт всё до `history-limit` |
| Объём пробы истории | 4000 строк; сам `history-limit` — 50 000 по настройке проекта |
| Цена истории | 89 байт на строку; 3000 строк = 266 КБ, 57 мс на стороне tmux |
| Второй alt-screen: `vim` | `alternate_on=1` — истории у приложения нет |
| Второй alt-screen: Claude Code, Codex | `alternate_on=0` — работают inline |
| mosh | на машине не установлен; вердикт по свойствам протокола, не по замеру |

Отсюда четыре следствия, на которых стоит всё остальное.

1. Причина «нет скролла офлайн» — не в xterm.js, а в alt-screen: у альтернативного буфера
   истории нет по стандарту, и ни один рендер её там не покажет.
2. Control mode снимает эту причину целиком и попутно убирает статусную строку tmux с
   экрана телефона, не трогая терминал IDE на том же сокете.
3. Подключение в control mode почти бесплатно — значит после обрыва можно продолжать, а не
   перерисовывать, если знать, что клиент уже видел.
4. Агентские TUI alt-screen не занимают. Это второй, отдельный alt-screen, который включает
   само приложение в панели: Claude Code и Codex работают inline, в alt-screen уходят vim и
   htop — там истории нет по природе, и это принимается.

Числа, выбранные (а не измеренные) на основании замеров:

| Величина | Значение | Откуда |
|---|---|---|
| Лимит истории на сессию | 10 000 строк ≈ 900 КБ | 89 байт на строку; 10 сессий ≈ 9 МБ |
| Порог включения эха | 50 мс | стартовое значение до замера на живом LTE |
| Таймаут неподтверждённого символа | 1 с | дальше предположение снимается с экрана |
| Глубина поиска рамки вверх | половина экрана | выше — это уже не рамка ввода |
| Высота экрана, ниже которой не скрываем | 10 строк | скрывать нечего и негде |
| Вариантов в вопросе агента | от 2 до 9 | вне диапазона кнопок нет |

## Вопросы задачи и вердикты

### 1. Своё окно терминала вместо библиотечного

**Вердикт: ядро xterm.js остаётся, «своим» становится вся обвязка вокруг него** (ADR 0013).

- Библиотечным остаётся ровно одно: разбор потока VT и отрисовка глифов.
- Своим становится всё остальное: как терминал подключается к tmux, где живёт история, чем
  пользователь пишет, что видно на экране, как ведут себя жесты и панели.
- Боли задачи не в рендере: скролл офлайн упирается в alt-screen, отзывчивость — в сетевой
  круг до Mac, полосы ввода — в раскладку экрана. Свой парсер не двигает ни одну из них.

Рассмотрено три варианта:

- **Ядро xterm.js плюс своя обвязка — принят.** Закрывает все боли задачи, а паритет с
  нынешним поведением сохраняется сам собой.
- **Свой рендер над `@xterm/headless` — в резерв.** Отдаёт аддоны WebGL, поиска и ссылок, а
  выигрыш нужен только при нестандартном виде экрана.
- **Свой эмулятор VT с нуля — отвергнут.** Месяцы на паритет (ширины Unicode, мыши SGR и
  X10, DEC-режимы, OSC 7/8/52, bracketed paste, IME) при нулевом движении по задаче.

### 2. Скролл в полноэкранных приложениях и офлайн

**Вердикт: причина — alt-screen, а не рендер; лечится сменой модели подключения плюс
историей на устройстве** (ADR 0014, ADR 0016).

- Сегодня `tmux attach` первым же байтом уводит клиента в alt-screen и держит там до
  detach; у альтернативного буфера scrollback отсутствует по стандарту.
- `tmux -CC attach` alt-screen не шлёт вообще — терминал живёт в обычном буфере, и
  локальный scrollback появляется сам собой.
- Второй alt-screen остаётся за приложением в панели. Claude Code inline по умолчанию,
  Codex получает `--no-alt-screen` в пресете запуска, vim и htop останутся без истории —
  такое приложение помечается в интерфейсе, чтобы это читалось как свойство, а не поломка.
- Офлайн закрывается тем, что история копится на телефоне, а не запрашивается у Mac:
  прокрутка перестаёт порождать сетевые запросы вообще.
- Лимит — 10 000 строк на сессию, старое вытесняется тихо.
- Шифрование персиста пользователь отклонил как непропорциональное; обоснование и цена
  решения — ADR 0016.
- Гостю по одноразовому коду локальная история не пишется никогда: сам гостевой scope
  описан в [docs/security.ru.md](security.ru.md), а это правило вводит уже наш план.
- Выход из аккаунта и отзыв устройства стирают сохранённую историю; механика отзыва —
  [docs/remote.ru.md](remote.ru.md).

### 3. Отзывчивость

**Вердикт: четыре названные точки — четыре разные причины и четыре разных ответа; ни одна
не лечится сменой библиотеки рендера.**

| Что раздражает | Почему так сейчас | Что делаем | Этап |
|---|---|---|---|
| Символ появляется не сразу | круг до Mac и обратно | локальное эхо | 4 (R06) |
| Скролл истории дёргается | каждый шаг — запрос по сети | история на телефоне | 2 (R06.5) |
| После тапа пусто | кадр ждёт полной перерисовки | кадр из локальной истории | 2 (R06.3) |
| Возврат после обрыва | реконнект = новый pty | возобновление по номеру | 3 (R06.4) |

- Две средние точки закрываются одним и тем же этапом 2: история уже лежит на телефоне, и
  ни прокрутка, ни первый кадр больше не ждут сети.
- Эхо предсказывает узкий и заведомо безопасный набор ввода, а приходящий вывод от Mac
  всегда побеждает; полный перечень исключений и состояний, где эхо молчит, — ADR 0015.
- Задержка до Mac показывается числом — чтобы «тормозит» перестало быть ощущением.

### 4. Полосы ввода и панель tmux

**Вердикт: рамка ввода агента скрывается, пока открыта своя строка ввода; статусная строка
tmux не приходит клиенту вовсе** (ADR 0017).

- Управляется тем же тумблером ✎, который сегодня открывает и закрывает свою строку ввода.
  Нового переключателя не появляется — это решение пользователя на брифинге.
- Рамка ищется снизу вверх по символам рисования, а её высота считается по факту каждый
  раз: в Claude Code рамка растёт вместе с черновиком.
- Статус работы и «esc to interrupt» переезжают в свою строку ввода, чтобы вместе с рамкой
  не пропала возможность прервать агента.
- Презумпция — «показать»: любое сомнение решается в пользу полной картинки, а перечень
  условий, при которых скрытие не срабатывает, задан ADR 0017.
- Скрытие — визуальное и только на клиенте: копирование и поиск видят полный экран, IDE на
  том же сокете видит всё как прежде.
- Статусная строка tmux отдельной работы не требует: в control mode её рисует клиент, и
  TermHub просто её не рисует.

### 5. mosh против tmux

**Вердикт: mosh как замена tmux отвергнут; три идеи его протокола берутся поверх нынешнего
WebSocket** (ADR 0015).

| Свойство mosh | Что оно ломает |
|---|---|
| входящий UDP 60000–61000 | обещание «на Mac ни одного входящего порта» |
| нет scrollback | главное требование задачи — листаемую историю |
| один клиент на сессию | телефон и терминал IDE в одной сессии |
| нет браузерного клиента | клиент TermHub — это PWA в браузере |

Что берётся:

- **Возобновление вместо перерисовки.** Агент нумерует куски вывода и держит кольцевой
  буфер; клиент при подключении называет номер последнего принятого, агент досылает
  пропущенное. Буфер не покрыл разрыв — один `capture-pane` и одна честная перерисовка.
- **Предиктивное эхо.** Набранное рисуется сразу и приглушённо, до ответа Mac; включается
  по измеренной задержке, а не всегда.
- **Роуминг.** Реконнект продолжает ту же сессию по её идентификатору, а не начинает новую:
  смена Wi-Fi на LTE и блокировка экрана перестают быть событием.

Ценность mosh — в идеях его протокола, а идеи переносимы на транспорт, который у продукта
уже есть.

### 6. Удобство работы с терминалом и с агентами

**Вердикт: четыре названные боли — четыре ответа; всё знание о конкретном агенте выносится
в профиль-данные, чтобы «и другие» из задачи не были пустым словом.**

| Боль | Ответ | Этап |
|---|---|---|
| На «1. Yes 2. No» целиться стрелками | варианты становятся кнопками | 6 |
| Непонятно, кто чего ждёт | карточка: последние строки и вопрос | 8 |
| Длинный промпт вслепую | редактор, диктовка, вложение картинки | 7 |
| Уведомление без текста | текст вопроса в push и ответ из него | 8 |

Профили агентов:

- В профиле-данных лежит всё, что TermHub знает про агента: имя процесса и заголовок,
  символы рамки, форма вопроса с вариантами, байты ответа на вариант, признаки «занят» и
  «ждёт ответа», аргументы запуска для пресета.
- Встроенных профилей два — Claude Code и Codex. Третий (Gemini CLI, aider, opencode) —
  новая запись, а не правка логики.
- Неизвестный агент получает базовое поведение: терминал, история, скролл, эхо, панели и
  жесты работают полностью; молчат только надстройки, которым нужен профиль.
- Не распознали — молчим. Отправка байтов по догадке в сессию с агентом, который умеет
  менять файлы, недопустима.
- Профиль как данные — ещё и страховка: агенты меняют вид экрана чаще, чем выходят релизы
  TermHub, а эвристика в коде ломается молча и целиком.

Жесты и навигация — та же строка задачи, только про терминал:

- Пинч меняет размер шрифта, и кнопки A−/A+ больше не нужны.
- Долгий тап выделяет слово с ручками, без переключения режима тумблером.
- Прыжок к предыдущей и к следующей команде и к последнему ответу агента — переход по
  границам блоков в обе стороны вместо прокрутки пальцем.
- Свайп влево-вправо меняет сессию, терминал при этом не пересоздаётся.

Ничего из уже работающего не теряется: заголовки сессий Claude и Codex, пресеты запуска,
индикатор активности и звонок, копирование при mouse tracking Codex, кликабельные пути и
ссылки OSC 8, compose bar и панель быстрых клавиш, тач-скролл и тач-выделение, read-only
гость через relay.

## Дорожная карта

Девять этапов. Порядок задан зависимостями, а не важностью: этап 1 — фундамент для 2 и 3.
Каждый этап — самостоятельная ценность и PR разумного размера.

| Этап | Что даёт пользователю | Зависит от |
|---|---|---|
| 1. Control mode | история листается, панели tmux нет, подключение мгновенное | — |
| 2. История на устройстве | скролл без сети и без рывков, первый кадр мгновенный | 1 |
| 3. Возобновление и роуминг | возврат после обрыва без перерисовки | 1 |
| 4. Предиктивное эхо | набранный символ появляется сразу | 3 |
| 5. Одна полоса ввода | рамка агента уходит, когда открыта своя строка | 1 |
| 6. Ответы кнопками | ответить агенту одним нажатием | 5 |
| 7. Редактор промпта | длинный текст, диктовка, картинка | 5 |
| 8. Дашборд и уведомления | видно, кто чего ждёт; ответ из уведомления | 6 |
| 9. Жесты и навигация | пинч, выделение, прыжки по блокам, свайп сессий | 2 |

Сквозное для всех этапов: кадры между агентом и вебом расширяются с объявлением
возможностей при подключении (ADR 0018). Агент на Mac и PWA в браузере обновляются в разное
время, а кэш service worker держит старую версию неделями — без объявления возможностей
обновление агента даёт пользователю чёрный экран.

### Этап 1. Control mode

- **Даёт.** История листается там, где раньше не листалось ничего; статусной строки tmux на
  телефоне нет; подключение к сессии перестаёт быть перерисовкой экрана.
- **Требования.** R01, R01.1, R01.2, R02, R03, R03.1, R03.2, G02.
- **Зависит от.** Ничего, это фундамент.
- **Делаем.** `tmux -CC attach` вместо `tmux attach`; разбор строчного протокола и
  разэкранирование октальных последовательностей; ввод через `send-keys -H`; размер окна
  через `refresh-client -C`; первый экран через `capture-pane -p -e -S -N`; `--no-alt-screen`
  в пресете Codex; пометка приложения, ушедшего в alt-screen.
- **Риск.** Протокол control mode привязан к версии tmux, а разэкранирование ложится на
  горячий путь. Поэтому откат на нынешний `tmux attach` обязателен: решение принимается один
  раз при подключении и пишет причину в лог. Это не дублирующая ветка «на всякий случай» —
  обе дороги уже существуют в коде.
- **Швы.** `control-protocol` (`parse`, `escapeInput`) и `session-link` (`open`, `write`,
  `resize`, `snapshot`). Тест — `control-protocol.parse` как чистая функция над байтами, без
  tmux и без DOM.

### Этап 2. История на устройстве

- **Даёт.** Прокрутка работает в самолётном режиме, не порождает сетевых запросов и не
  дёргается; сессия показывает картинку сразу после тапа; история переживает перезапуск PWA.
- **Требования.** R04, R04.1–R04.5, R16i, R06.3, R06.5, A02.
- **Зависит от.** Этап 1: без обычного буфера копить нечего.
- **Делаем.** Вывод копится в обычном буфере xterm и пишется в хранилище браузера порциями;
  лимит 10 000 строк на сессию с тихим вытеснением; срез `capture-pane` при первом открытии
  сессии; первый кадр рисуется из локальной истории до сети; размер истории и кнопка очистки
  — в настройках; гостю по одноразовому коду история не пишется вовсе, а выход из аккаунта
  и отзыв устройства её стирают — механика отзыва в [docs/remote.ru.md](remote.ru.md).
- **Риск.** Квоты мобильных браузеров и их политика вытеснения: хранилище сайта может быть
  очищено без участия пользователя. Недоступное хранилище — работаем в памяти и пишем в лог,
  а не падаем; потерянное восстанавливается срезом с Mac. Обрыв записи не должен ломать
  чтение: хвост без завершающей записи отбрасывается.
- **Швы.** `term-history` (`append`, `read`, `clear`, `size`). Проверяется существующими
  моками транспорта и хранилища в вебе.

### Этап 3. Возобновление и роуминг

- **Даёт.** После обрыва экран продолжается с места, а не перерисовывается; смена Wi-Fi на
  LTE и блокировка телефона не рвут сессию.
- **Требования.** R06.4, R14i, A01.
- **Зависит от.** Этап 1: дешёвое подключение — условие возобновления.
- **Делаем.** Агент нумерует куски вывода и держит кольцевой буфер; клиент при подключении
  называет номер последнего принятого; реконнект продолжает ту же сессию по идентификатору;
  задержка до Mac показывается числом.
- **Риск.** Буфер не покрыл разрыв на быстром выводе (`yes`, сборка) — тогда честный
  `capture-pane` и одна перерисовка, а не тихая дыра. Дубли после реконнекта опаснее
  пропусков: пропуск виден, дубль — нет.
- **Швы.** `session-link` (`resumeFrom`, нумерация, кольцевой буфер). Проверяется на
  изолированном tmux-сокете в тестах агента.

### Этап 4. Предиктивное эхо

- **Даёт.** Набранный символ виден сразу, ещё до ответа Mac.
- **Требования.** R06, R06.1, R06.2.
- **Зависит от.** Этап 3: без нумерации вывода нечем подтверждать предположение.
- **Делаем.** Предсказание набора ввода, заданного ADR 0015; неподтверждённое рисуется
  приглушённо и снимается приходящим выводом либо по таймауту 1 с; включение по измеренной
  задержке; в состояниях терминала, перечисленных там же, эхо выключается целиком.
- **Риск.** Эхо рисует то, чего Mac ещё не видел. При отказе отправки оно обязано исчезнуть,
  иначе пользователь поверит в отправленное. Порог включения — 50 мс как стартовое значение
  до замера на живом LTE; это единственное число плана, которое нельзя выбрать за столом.
- **Швы.** `echo` (`predict`, `confirm`, `reset`, `enabled`).

### Этап 5. Одна полоса ввода

- **Даёт.** На экране одна полоса ввода вместо двух, и место на телефоне возвращается.
- **Требования.** R07, R07.1, G01, G01.1, G01.2, R11.1, R11.2.
- **Зависит от.** Этап 1: распознавание работает по снимку обычного буфера.
- **Делаем.** Распознавание рамки по символам рисования; визуальное скрытие региона, пока
  открыта своя строка; статус работы и «esc to interrupt» в своей строке; профили агентов
  появляются здесь же, как данные.
- **Риск.** Ошибка детектора в сторону «скрыл лишнее» стоит дороже, чем «показал лишнее»:
  пользователь не увидит вопроса и решит, что агент завис. Отсюда презумпция «показать» и
  мгновенный возврат по закрытию своей строки.
- **Швы.** `agent-ui.frame` и `agent-profiles` (`profiles`, `match`). Тест — чистые функции
  на зафиксированных снимках экрана Claude Code, Codex и неизвестного агента, на котором
  надстройки обязаны промолчать.

### Этап 6. Ответы кнопками

- **Даёт.** Ответ агенту одним нажатием вместо прицеливания стрелками.
- **Требования.** R11, R11.1.
- **Зависит от.** Этап 5: нужны профили и распознавание экрана.
- **Делаем.** Блок «номер, разделитель, текст» от двух до девяти вариантов подряд с единицы
  превращается в кнопки; кнопка шлёт ровно то, что набрал бы человек — цифру и `Enter`, а
  для «(y/n)» букву без `Enter`; соответствие «вариант → байты» берётся из профиля, а не
  угадывается; подсветка текущего варианта, если агент рисует курсор.
- **Риск.** Ложные кнопки в сессии с агентом, который меняет файлы. Не распознали, номера не
  подряд, агент неизвестен или сессия только на чтение — кнопок нет, обычный ввод работает;
  вопрос ушёл с экрана — кнопки гаснут вместе с ним.
- **Швы.** `agent-ui.question` и `agent-profiles`. Тестируется на тех же снимках экрана.

### Этап 7. Редактор промпта

- **Даёт.** Длинный промпт пишется в нормальном поле, диктуется голосом, к нему
  прикладывается картинка.
- **Требования.** G09, G09.1, G10, G11.
- **Зависит от.** Этап 5: своя строка ввода — то место, ради которого скрывается рамка.
- **Делаем.** Многострочное поле с курсором, выделением и правкой середины; черновик
  переживает сворачивание приложения и переключение сессий; кнопка диктовки рядом со строкой,
  а само распознавание — средствами клавиатуры телефона: своего движка не заводим; картинка
  ложится во временную папку на Mac, а в промпт подставляется путь.
- **Риск.** Потерянный черновик обесценивает этап целиком, поэтому черновик хранится, а не
  живёт в памяти вкладки. Заготовок промптов здесь нет намеренно: лечится процесс набора, а
  не обвес вокруг него.
- **Швы.** `prompt-editor` (`mount`, `draft`, `send`).

### Этап 8. Дашборд и уведомления

- **Даёт.** Видно, кто чего ждёт, без захода в каждую сессию; ответить «да» можно прямо из
  уведомления.
- **Требования.** G06, G08, G08.1.
- **Зависит от.** Этап 6: кнопки ответа и разбор вопроса уже есть.
- **Делаем.** Карточка сессии показывает последние строки вывода и сам вопрос; ждущие идут
  первыми; текст вопроса или итога кладётся в push; кнопки ответа шлют байты в сессию без
  открытия приложения. Устройство push и требования к HTTPS —
  [docs/notifications.ru.md](notifications.ru.md).
- **Риск.** Ответ из уведомления может не дойти — Mac спит, сессия убита: уведомление обязано
  сказать об этом, а не промолчать. На вопрос, отвеченный и с телефона, и в IDE, выигрывает
  первый, второй получает отказ, а не дубль. Текст вопроса виден на локскрине — это принято
  пользователем на брифинге.
- **Швы.** Существующие уведомления и дашборд веба плюс `agent-ui.question` как источник
  текста. Ответ требует права записи: гостю только на чтение кнопок нет.

### Этап 9. Жесты и навигация

- **Даёт.** Пинч вместо кнопок A−/A+, выделение долгим тапом вместо тумблера режима, прыжки
  к предыдущей и следующей команде и к последнему ответу агента, свайп между сессиями.
- **Требования.** G04, G04.1, G05, G07.
- **Зависит от.** Этап 2: без локальной истории прыгать не по чему.
- **Делаем.** Разметку границ блоков по локальной истории и переход по ним в обе стороны;
  пинч с порогом по числу пальцев и дистанции; выделение слова с ручками; свайп по порядку
  вкладок без зацикливания на краю.
- **Риск.** Жесты конфликтуют друг с другом и с выделением. Один палец — всегда скролл; при
  активном выделении жест отдаётся выделению; прерванный свайп возвращает текущую сессию, не
  пересоздавая терминал. Пинч меняет размер окна tmux всем клиентам сессии — ровно то же
  поведение, что у кнопок A−/A+ сегодня.
- **Швы.** `agent-ui.blocks` и существующий тач-слой веба.
