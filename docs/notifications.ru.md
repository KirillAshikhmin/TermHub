# Уведомления

[English](notifications.md) · **Русский**

## Как это работает

TermHub узнаёт, что сессия «звонит» (bell), двумя путями: пока вы смотрите
в открытый терминал — сканирует сырой байт BEL (`0x07`) прямо в выводе; для
остальных сессий — раз в 2 секунды опрашивает флаг tmux
`window_bell_flag` (поэтому в `~/.tmux.conf` нужна опция `monitor-bell on` —
её вместе с остальными настройками дописывает `termhub setup`).

Дальше — три канала доставки:

1. **Вкладка открыта** — звук (разблокируется первым тапом по экрану, так
   требуют браузеры) + системное `Notification`.
2. **Приложение закрыто** — Web Push прямо с Mac (нужен HTTPS-контекст
   подписки, см. ниже).
3. **Remote-режим** — то же самое: подписка на push тоже передаётся агенту
   через E2E-канал, сама отправка не отличается от LAN.

Троттлинг: не чаще одного пуша на сессию в 30 секунд, чтобы серия звонков
не заваливала уведомлениями.

## Включить звук у Claude Code (`terminal_bell`)

Чтобы Claude Code действительно слал BEL, когда ждёт вашего ответа, у него
в `~/.claude/settings.json` должно быть:

```json
{ "preferredNotifChannel": "terminal_bell" }
```

В некоторых терминалах (Ghostty, Kitty, iTerm2) по умолчанию вместо этого
используется системное уведомление самого терминала — TermHub его не
увидит, ему нужен именно `terminal_bell`. Настройте один раз и запускайте
Claude Code внутри tmux-сессии (то есть через `tm`, см. README) — тогда BEL
долетит и до TermHub.

## Локальные уведомления (Android/desktop)

Работают из коробки, если разрешить их кнопкой «Разрешить уведомления» в
шапке приложения. Без явного разрешения браузера TermHub уведомление не
покажет — оно никогда не запрашивается автоматически.

## Web Push (когда приложение закрыто)

VAPID-ключи генерируются автоматически при `termhub setup` — ничего
дополнительно настраивать не нужно. Но сама подписка на push (как и
установка PWA) работает только в защищённом контексте (HTTPS, а также
`localhost`), поэтому по обычному `http://<mac>.local:7710` (LAN) push
недоступен — сайт при этом работает как обычно, просто без push и без
предложения установить приложение.

Получить HTTPS для локального адреса можно двумя путями.

### Вариант 1: Tailscale (`tailscale cert`)

Если Mac и телефон в одной сети Tailscale:

```bash
tailscale cert <ваш-tailscale-hostname>
```

Команда положит `<hostname>.crt`/`<hostname>.key` в текущий каталог.
Пропишите пути в `~/.termhub/config.json`:

```json
"tls": { "cert": "/путь/<hostname>.crt", "key": "/путь/<hostname>.key" }
```

и перезапустите `termhub start`. Откройте `https://<hostname>:7710` —
сертификат настоящий (доверенный, через Let's Encrypt), браузер ругаться не
будет.

### Вариант 2: mkcert (локальный сертификат для `.local`/IP)

```bash
brew install mkcert
mkcert -install                        # один раз — ставит корневой сертификат в систему
mkcert <имя-mac>.local <IP-мака>        # например: mkcert macbook.local 192.168.1.42
```

Появятся два файла: `*.pem` (сертификат) и `*-key.pem` (ключ). Пропишите их
в `~/.termhub/config.json`:

```json
"tls": { "cert": "/путь/до/<имя>.pem", "key": "/путь/до/<имя>-key.pem" }
```

и перезапустите агента — адрес станет `https://<имя-mac>.local:7710`.

Важно: mkcert-сертификату доверяют только машины, куда вручную поставлен
его корневой сертификат (`mkcert -install`, путь к корню — `mkcert -CAROOT`).
На телефоне браузер по умолчанию такому сертификату не доверяет — либо
переносите корневой сертификат на телефон вручную, либо используйте
вариант с Tailscale — там сертификат доверенный из коробки.

## iOS: установка PWA на домашний экран

На iPhone Web Push и полноценная офлайн-работа доступны только приложению,
установленному на домашний экран — обычная вкладка Safari их не получает:

1. Откройте TermHub по HTTPS (см. выше) в Safari.
2. «Поделиться» → «На экран Home».
3. Требуется iOS 16.4 или новее.
4. Уведомления запрашиваются уже из установленного приложения — кнопкой
   «Разрешить уведомления» в шапке.
