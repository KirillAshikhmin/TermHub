# Чек-лист ручной проверки

[English](manual-test-checklist.md) · **Русский**

Проверка на двух платформах — iPhone Safari и Android Chrome. Пункты,
отмеченные 📱, требуют реального телефона (эмулятор и мобильный режим
DevTools их не покрывают: нужны настоящие push-уведомления, установка PWA
на домашний экран, реальная мобильная клавиатура).

## Вход

- [ ] Открыть `http://<mac>.local:7710` (или IP — см. README → Troubleshooting)
- [ ] Ввести правильный пароль — попадаем на дашборд, cookie сохраняется
      (повторный заход в течение 30 дней не требует пароля)
- [ ] Ввести неправильный пароль — понятная ошибка, без раскрытия деталей
- [ ] 5 неверных попыток подряд с одного устройства — блокировка входа на
      минуту (сообщение о превышении лимита)

## Дашборд

- [ ] Пустой список сессий — подсказка «запустите `tm` в терминале IDEA»
- [ ] Карточка сессии — имя, каталог (усечён при необходимости), текущая
      команда (`zsh`/`claude`/…), «активность N мин назад», счётчик
      подключённых клиентов
- [ ] Индикатор 🔔 у сессии с bell (см. раздел «Push-уведомления» ниже)
- [ ] Создать сессию (имя + каталог из списка + пресет `zsh`/`claude`) —
      появляется в списке и подтверждается `tmux ls` на Mac
- [ ] Завершить сессию (с подтверждением) — пропадает из списка и из
      `tmux ls`
- [ ] Список сам обновляется (поллинг ~3 с) при видимой вкладке

## Терминал

- [ ] Открыть сессию — виден реальный вывод tmux-сессии
- [ ] Ввод с телефонной клавиатуры доходит и отображается корректно
- [ ] Панель быстрых клавиш: Esc, Tab, Shift+Tab, стрелки, Enter, Ctrl+C,
      y/n — каждая шлёт ожидаемую последовательность
- [ ] A− / A+ меняют размер шрифта терминала, значение сохраняется между
      сессиями
- [ ] 📱 Поворот телефона / появление экранной клавиатуры — терминал
      ресайзится без обрезки текста
- [ ] 📱 Отключить и снова включить Wi-Fi/мобильный интернет — виден баннер
      «переподключение», после восстановления сети терминал сам
      восстанавливает соединение

## PWA-установка (нужен HTTPS — см. docs/notifications.md)

- [ ] 📱 iPhone Safari: «Поделиться» → «На экран Home» (iOS ≥ 16.4), иконка
      на рабочем столе открывает TermHub как отдельное приложение
- [ ] 📱 Android Chrome: браузер сам предлагает «Установить приложение» или
      пункт появляется в меню; после установки открывается без адресной
      строки

## Push-уведомления

- [ ] Нажать «Разрешить уведомления» в шапке — браузер запрашивает разрешение
- [ ] Включить `terminal_bell` у Claude Code (см. docs/notifications.md),
      дождаться, когда Claude Code «звякнет» — при открытой вкладке звук +
      системный `Notification`
- [ ] 📱 Свернуть приложение или заблокировать телефон, дождаться bell —
      прилетает push-уведомление с именем сессии
- [ ] Несколько bell подряд за 30 секунд — уведомление приходит не чаще
      одного раза на сессию (троттлинг)

## Remote (relay)

- [ ] Поднят relay (`docker compose up -d`, см. docs/remote.md), у агента
      в конфиге задан `relayUrl`
- [ ] На Mac: `termhub share` — показывает код `XXXX-YYYY-YYYY-YYYY` и QR
- [ ] 📱 На телефоне: открыть PWA по адресу relay, «Добавить по коду»,
      ввести код (или отсканировать QR) — устройство спарено
- [ ] 📱 С телефона в remote-режиме: виден список сессий агента, можно
      открыть терминал, ввод/вывод работают так же, как в LAN
- [ ] С другого компьютера: `termhub pair <код> --relay <url>`, затем
      `termhub connect` — терминал открывается в CLI, ввод/вывод/ресайз
      работают
- [ ] `termhub devices` показывает оба спаренных устройства;
      `termhub revoke <fingerprint>` — устройство теряет доступ (следующее
      подключение отклоняется)
