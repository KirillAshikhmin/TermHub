# Чек-лист ручной проверки

[English](manual-test-checklist.md) · **Русский**

Проверка на двух платформах — iPhone Safari и Android Chrome. Пункты,
отмеченные 📱, требуют реального телефона (эмулятор и мобильный режим
DevTools их не покрывают: нужны настоящие push-уведомления, установка PWA
на домашний экран, реальная мобильная клавиатура).

## Вход

- [ ] Открыть `http://<mac>.local:7710` (или IP — см. README → Troubleshooting)
- [ ] Ввести правильный пароль — попадаем на дашборд, cookie сохраняется
      (повторный заход в течение 30 дней не требует пароля)
- [ ] Ввести неправильный пароль — понятная ошибка, без раскрытия деталей
- [ ] 5 неверных попыток подряд с одного устройства — блокировка входа на
      минуту (сообщение о превышении лимита)

## Дашборд

- [ ] Пустой список сессий — подсказка «запустите `tm` в терминале IDEA»
- [ ] Карточка сессии — имя, каталог (усечён при необходимости), текущая
      команда (`zsh`/`claude`/…), «активность N мин назад», счётчик
      подключённых клиентов
- [ ] Индикатор 🔔 у сессии с bell (см. раздел «Push-уведомления» ниже)
- [ ] Создать сессию (имя + каталог из списка + пресет `zsh`/`claude`/`codex`) —
      появляется в списке и подтверждается `tmux ls` на Mac
- [ ] Завершить сессию (с подтверждением) — пропадает из списка и из
      `tmux ls`
- [ ] Список сам обновляется (поллинг ~3 с) при видимой вкладке

## Терминал

- [ ] Открыть сессию — виден реальный вывод tmux-сессии
- [ ] Ввод с телефонной клавиатуры доходит и отображается корректно
- [ ] Создать сессию с пресетом `codex` — вкладка сессии показывает имя потока
      Codex (или идентификатор до появления имени), а заголовок браузера/PWA имеет
      вид `<отображаемое имя> · TermHub`
- [ ] В этой сессии Codex выполнить `/rename Проверка копирования` — не позднее
      следующего опроса списка существующая вкладка и browser title обновляются на
      месте, а имя самой tmux-сессии не меняется
- [ ] В процессе Codex, запущенном без пресета, выполнить `/title`, добавить
      `thread-title`, затем `/rename Проверка старой сессии` — TermHub показывает
      это имя без пересоздания или переименования tmux-сессии
- [ ] В Codex на macOS (при активном mouse tracking) удерживать `Option` и выделить
      вывод drag-ом — при отпускании указателя текст автоматически копируется;
      после сброса подсветки перерисовкой `Command+C` всё ещё копирует последнее
      непустое выделение. Drag без `Option` продолжает доходить до TUI Codex
- [ ] Выделить drag-ом вывод в Claude Code — при отпускании указателя текст
      автоматически копируется; после сброса подсветки перерисовкой
      `Command+C`/`Ctrl+C` всё ещё копирует последнее непустое выделение
- [ ] Запустить foreground-команду без выделения терминала и нажать `Ctrl+C` —
      interrupt доходит до процесса, обработчик копирования его не поглощает
- [ ] Панель быстрых клавиш: Esc, Tab, Shift+Tab, стрелки, Enter, Ctrl+C,
      y/n — каждая шлёт ожидаемую последовательность
- [ ] A− / A+ меняют размер шрифта терминала, значение сохраняется между
      сессиями
- [ ] 📱 Поворот телефона / появление экранной клавиатуры — терминал
      ресайзится без обрезки текста
- [ ] 📱 Отключить и снова включить Wi-Fi/мобильный интернет — виден баннер
      «переподключение», после восстановления сети терминал сам
      восстанавливает соединение
- [ ] Вернуться из рабочего пространства сессии на дашборд/экран входа/пейринг —
      заголовок браузера/PWA снова становится `TermHub`

### Способ подключения и альтернативный экран

- [ ] Открыть сессию — чип в шапке называет работающий способ подключения
      (`control mode`), и тот же режим виден в логе агента
- [ ] Нажать на чип — сообщение «При следующем открытии терминала: attach», чип
      помечен как ожидающий, но текущий терминал продолжает работать в прежнем
      режиме (ввод/вывод не прерываются)
- [ ] Вернуться к списку сессий и открыть сессию снова — чип показывает `attach`;
      вернуть переключатель обратно в `control mode`
- [ ] Задать в конфиге агента `"terminalMode": "attach"` и перезапустить его —
      просьба клиента про `control mode` игнорируется: чип показывает `attach` и
      помечен как перебитый — нажатие объясняет, что режим выбирает агент
      (настройка агента старше просьбы)
- [ ] В сессии с Claude/Codex (control mode) листать вывод пальцем — история
      листается локально, без сети, и статусной строки tmux не видно
- [ ] Запустить в сессии `vim` (или `htop`) — появляется пометка
      «Полноэкранное приложение»; нажатие на неё объясняет, что истории у такого
      приложения нет, а тач-драг листает уже само приложение
- [ ] Выйти из `vim` — пометка исчезает, история снова листается локально
- [ ] Открыть «Диагностика» — строка «Способ подключения терминала (последний
      известный)» называет режим последнего подключения (агент режим в диагностике
      не отдаёт — строка про последний кадр состояния, в том числе от другого
      агента), «Просьба клиента» — выбранный переключателем

## Проводник

- [ ] Открыть текстовый файл, изображение, медиа, бинарный и слишком большой/
      усечённый файл — в подвале каждого viewer есть кнопка «Открыть на хосте»
      рядом с уже существующими действиями
- [ ] Нажать «Открыть на хосте» — ровно одно приложение по умолчанию открывает этот
      файл на Mac с агентом TermHub, появляется сообщение об успехе, а viewer
      остаётся открытым
- [ ] Вызвать ошибку системного opener — показан текст ошибки агента, viewer остаётся
      открытым, кнопку можно нажать повторно
- [ ] Подключить read-only relay-гостя с доступом к файлам — preview работает, но
      кнопки «Открыть на хосте» нет

## PWA-установка (нужен HTTPS — см. docs/notifications.md)

- [ ] 📱 iPhone Safari: «Поделиться» → «На экран Home» (iOS ≥ 16.4), иконка
      на рабочем столе открывает TermHub как отдельное приложение
- [ ] 📱 Android Chrome: браузер сам предлагает «Установить приложение» или
      пункт появляется в меню; после установки открывается без адресной
      строки

## Push-уведомления

- [ ] Нажать «Разрешить уведомления» в шапке — браузер запрашивает разрешение
- [ ] Включить `terminal_bell` у Claude Code (см. docs/notifications.md),
      дождаться, когда Claude Code «звякнет» — при открытой вкладке звук +
      системный `Notification`
- [ ] 📱 Свернуть приложение или заблокировать телефон, дождаться bell —
      прилетает push-уведомление с именем сессии
- [ ] Несколько bell подряд за 30 секунд — уведомление приходит не чаще
      одного раза на сессию (троттлинг)

## Remote (relay)

- [ ] Поднят relay (`docker compose up -d`, см. docs/remote.md), у агента
      в конфиге задан `relayUrl`
- [ ] На Mac: `termhub share` — показывает код `XXXX-YYYY-YYYY-YYYY` и QR
- [ ] 📱 На телефоне: открыть PWA по адресу relay, «Добавить по коду»,
      ввести код (или отсканировать QR) — устройство спарено
- [ ] 📱 С телефона в remote-режиме: виден список сессий агента, можно
      открыть терминал, ввод/вывод работают так же, как в LAN
- [ ] С другого компьютера: `termhub pair <код> --relay <url>`, затем
      `termhub connect` — терминал открывается в CLI, ввод/вывод/ресайз
      работают
- [ ] `termhub devices` показывает оба спаренных устройства;
      `termhub revoke <fingerprint>` — устройство теряет доступ (следующее
      подключение отклоняется)
