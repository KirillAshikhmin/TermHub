# 0012. Занятость имени в `tm` — по `list-sessions`, а не пробой `has-session -t "=<имя>"` (D01)

## Контекст

План (первая редакция §10 спецификации) проверял занятость кандидата пробой
`tmux -L termhub has-session -t "=<кандидат>"`: `=` в цели tmux — точное совпадение
имени сессии, ответ — код возврата, без разбора вывода и grep.

## Решение

Пробы через `-t` нет ни в каком виде — занятость определяется точным совпадением
кандидата с целой строкой вывода `tmux -L termhub list-sessions -F '#{session_name}'`
(в духе `grep -qxF`); отсутствие сервера — пустой список, имя свободно.

## Почему

Craft-ревью таска 04 на живом tmux 3.7b: при существующей сессии `foo.bar` проба
`has-session -t "=foo.bar"` отвечает «can't find pane: bar». Точка и двоеточие в цели
`-t` остаются разделителями `session:window.pane` и после `=`: `=foo.bar` для tmux —
«сессия foo, панель bar». Кандидат считался свободным, `new -s foo.bar` падал с
«duplicate session» — тот самый отказ, ради устранения которого функция
переписывалась, и на каждой папке с точкой в имени (`v1.1`, `my.app`). Предположение
плана верно для `foo`, но не для имени с разделителем, а экранировать разделитель в
цели tmux нельзя.

Отвергнут обход через санитизацию базы — заменять точку, как делает веб (`my.app` →
`my_app`): это переименовало бы все сессии, которые `tm` до сих пор заводил как есть,
а единая санитизация веба и `tm` — отдельный вопрос вне рамок задачи. Отвергнут
вариант без проверки вовсе — «пробовать `new -s`, по ошибке брать следующий номер»:
`new -s` без `-d` — это attach, попытка не бывает сухой, а разбор stderr tmux в шелле
хрупче списка имён. Сравнение по списку нечувствительно к разделителям цели, остаётся
точным (`MyProject` не совпадает с `MyProject1`) и не зависит от того, как tmux
разбирает цель.

## Последствия

На каждый кандидат — `list-sessions` и проход по списку вместо одного кода возврата;
для десятков сессий незаметно. Правило шире `tm`: `has-session -t "=<имя>"` — не
проверка занятости ни в одной будущей шелл-обёртке. На агенте дорога закрыта дважды —
занятость и так читается из `list-sessions` (ADR 0008), а `NAME_RE` (`^[\w-]{1,40}$`)
точку не пропускает; в `tm` валидации нет, база берётся из `basename` как есть, поэтому
тест на папку `foo.bar` обязателен. Подложный `tmux` в тестах воспроизводит только то,
что в него заложили: найдено это живым tmux, не тестом, и живая проверка на имени с
точкой остаётся частью приёмки любой правки `tm`.
