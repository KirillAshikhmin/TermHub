# 0034. Control mode: снимок возвращает состояние панели, а экран клиента принимает её размер

## Контекст

Жалоба: control mode «иногда криво отрисовывает терминал», attach — нет. Ревью 10.11.2026
нашло три причины, все — следствие одного свойства control mode: tmux отдаёт клиенту поток
байтов панели как есть и сам экран клиента не ведёт (в attach он рисует его целиком).

1. **Курсор и режимы.** Снимок (`capture-pane -p -e`) — только текст экрана. Курсор клиента
   после него стоял в конце последней строки, а не там, где курсор панели; режимы, которые
   приложение включило до подключения (вставка в скобках, клавиши курсора, мышь,
   альтернативный экран), клиент не знал вовсе. Приложение, перерисовывающее себя
   относительными сдвигами (рамка ввода Claude Code), рисовало со смещением; многострочная
   вставка уходила без скобок.
2. **Размер.** `refresh-client -C` — просьба, а не приказ: при `window-size latest` окно
   держит последний активный клиент. Замер на изолированном сокете: control-клиент просит
   30×5, рядом подключён обычный клиент 80×24 — панель остаётся 80×23. Экран клиента при
   этом был своего размера, и вывод панели ложился на него с переносами и сдвигом. У
   владельца системный терминал подключён к тем же сессиям постоянно.
3. **Relay.** Терминал создаётся на OPEN с размером по умолчанию, размер клиента приезжает
   следующим кадром. Снимок, успевший раньше, был разложен под 80×24.

## Решение

- Следом за `capture-pane` уходит запрос состояния панели (`TH-STATE,…` через
  `display-message`). Команды идут подряд, до первого ответа. `renderSnapshot` дописывает к
  снимку сброс цвета, позицию курсора и режимы. На обычном экране курсор ставится
  **относительно** конца снимка (вверх и вправо): экран клиента бывает выше панели, и
  абсолютная строка не совпала бы. В альтернативном экране клиент сначала сам входит в него
  (`?1049h`), там позиции абсолютные и восстанавливается область прокрутки.
- Вывод глушит только сам снимок: пришедшее между его концом и ответом о состоянии в снимок
  не попало и идёт на экран.
- Размер панели едет клиенту кадром состояния (`TerminalState {cols, rows}`, поля
  независимы — ADR 0018): при подключении и на каждый `%layout-change`. Экран клиента
  принимает размер панели и показывает пометку «размер задаёт другой клиент tmux»; свою
  просьбу о размере он повторяет только когда она сама изменилась — иначе два клиента
  перетягивали бы окно на каждое нажатие.
- Через relay снимок ждёт первого `resize()` клиента (не дольше 700 мс).

## Что осталось

- Смена активной панели или окна внутри сессии экран не пересобирает: вывод новой панели
  ложится поверх старой картинки до первой полной перерисовки приложением.
- Область прокрутки на обычном экране не восстанавливается (её установка уводит курсор).
- Смена размера панели не пересобирает экран: приложение перерисовывается само по
  SIGWINCH, а строки оболочки tmux и xterm переносят каждый по-своему.
