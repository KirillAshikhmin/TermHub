# 0020. Запрет альтернативного экрана отменён: приложениям он снова разрешён

> Отменяет ADR 0019 (13.09.2026).

## Контекст

ADR 0019 запретил альтернативный экран на сокете агента: `alternate-screen off` держал
приложение в обычном буфере, и вывод работающего Claude Code впервые ложился в scrollback
панели и в локальную историю на устройстве.

Решение выглядело верным и опиралось на верный замер. Работающий Claude Code действительно
занимает альтернативный экран — проверено на живых сессиях владельца 13.09.2026: семь панелей
из двенадцати, и все семь Claude. У альтернативного буфера истории нет по стандарту, значит в
агентских сессиях — ровно тех, ради которых затевались этапы 1 и 2, — копить её было не из
чего. Запрет чинил это одной настройкой на своём сокете, а его цену (кадры перерисовки в
истории, невосстановленный экран после vim, общее действие на терминал IDE) владелец принял
сознательно.

Запрет прожил один день. На живом сокете он уже снят руками; этот ADR убирает его из кода.

## Решение

Агент не трогает опцию `alternate-screen`. Приложение в панели вправе занять альтернативный
экран, как и по умолчанию, — и работающий Claude Code его занимает.

Из кода уходит вся механика: установка опции на старте агента, склейка с созданием первой
сессии, защёлка перевзвода при пропаже сервера tmux и тесты этой механики. Выключенного флага
и настройки, которую никто не включит, после этого не остаётся: мёртвый код с такой настройкой
хуже отсутствия кода.

## Почему

Цена оказалась не там, где её считали. Без альтернативного экрана Claude Code печатает свой
полноэкранный интерфейс прямо в обычный буфер, и его рамка ввода становится частью потока:
при любом листании она уезжает вверх вместе с выводом, а на её месте остаются кадры
перерисовки. Человек смотрит в терминал с телефона ровно затем, чтобы прочитать напечатанное
и ответить агенту, — и обе половины сценария ломаются разом, причём вторая насовсем: ответить
в рамку, которой нет на экране, нельзя.

Получается, что история покупается ценой того, ради чего история нужна. Обещание этапа 1 в
сессиях Claude не выполнено ни так, ни так: листать поток, из которого уезжает рамка ввода,
человек не станет.

Отвергнут на сегодня вариант «спрятать рамку агента и дать свою строку ввода»: он снимает
именно эту цену — рамка перестаёт быть частью картинки, а ввод живёт в своей строке внизу
экрана. Это пятый этап дорожной карты (ADR 0017), и владелец его пока не выбрал; до него
возвращать запрет не на что.

Отвергнут вариант «оставить механику, но за выключенной настройкой»: это код, который никто
не включит, и вместе с ним вторая ветка поведения терминала, которую придётся держать в
голове при каждой правке. Вернуть решение из истории git дешевле, чем носить его выключенным.

## Последствия

В сессиях Claude Code истории снова нет: буфер альтернативный, scrollback у него отсутствует
по стандарту, и локальная история на устройстве (ADR 0016) в таких сессиях не наполняется.
Это открытый вопрос, над которым идёт отдельная работа, а не закрытый компромисс: обещание
этапа 1 для главного сценария остаётся невыполненным, и ответ на него ищется не в настройках
tmux.

Пометка «Полноэкранное приложение» снова загорается там, где ей положено — vim, htop и
работающий Claude Code. Механика пометки из ADR 0014 остаётся единственным, что человек
видит на месте истории, и объяснять ему приходится именно ею.

Обратная сторона возвращается вместе с запретом: экран после выхода из vim снова
восстанавливается, кадры перерисовки полноэкранного интерфейса в историю не попадают, лимит
10 000 строк на сессию расходуется по замеру «89 байт на строку», а терминал IDE на том же
сокете больше не получает чужую настройку.

Замер при этом остаётся в силе и никуда не девается из документов: работающий Claude Code
занимает альтернативный экран. Отменено решение запрещать, а не факт, из которого оно росло.
