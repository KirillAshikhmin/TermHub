# 0050. Экран агента узнаётся по строке ввода, а не по точному виду подвала

Дата: 12.11.2026

## Задача

Чат читает экран панели, чтобы понять, что агент ждёт ввода, работает или задаёт вопрос, и
только на узнанном экране нажимает клавиши. Первая версия считала экран узнанным, когда
подвал под строкой ввода совпадал с измеренным видом. За один вечер работы на живых сессиях
владельца это правило отказало шесть раз: список фоновых агентов под подвалом Claude, подпись
в линейке рамки ввода Claude, пользовательская строка состояния Codex, подсказка «tab to queue
message», уведомление «⚠ N warnings · f2 to view», пункт «⇧← queued messages» в подвале
вопроса. Каждый раз агент рисовал подвал чуть иначе, чем на замере, и чат уходил в окно
терминала или не отправлял запрос.

## Решение

- **«Агент у строки ввода» узнаётся по самой строке ввода**: у Codex — последний блок со
  знаком «›», нарисованным отдельно от текста, с пустой строкой и подвалом до четырёх строк
  под ним; у Claude — рамка из двух линеек со знаком ввода и до восьми строк под ней.
- **Подвал только читается**: из него берутся режим, состояние, модель, подсказка очереди,
  число фоновых агентов и команд — когда они там есть. Незнакомая строка или пункт экран
  неузнанным не делают.
- **Диалог узнаётся по строению** — вопрос, пронумерованные варианты, указатель, — а начало
  его подсказки называет вид диалога; хвост подсказки свободный.
- **Агент обязан быть в панели**: определитель отвечает «жив», и команда панели — команда
  этого агента. Иначе чат отказывает до вставки текста, что бы ни осталось на экране. Смена
  команды панели посреди действия останавливает действие.
- **Безопасность держится на сверке, а не на подвале**: клавиша отправки уходит, только если
  вставленный текст виден в строке ввода свежего экрана; ответ на вопрос — только при
  совпавшем отпечатке.

## Отвергнуто

- **Добавлять в правило каждый новый вид подвала.** Так чинились первые пять отказов; шестой
  пришёл в тот же вечер. Подвал настраивается пользователем и меняется от состояния, очереди
  и предупреждений — перечислить его виды нельзя.
- **Узнавать диалог только по строению, без подсказки.** Вопрос с вариантами неотличим от
  меню модели, где цифра меняет модель: карточка с кнопками одобрила бы не то.
- **Не проверять команду панели, раз экран узнан.** После выхода Claude его последний кадр
  остаётся на экране; со свободным подвалом он читался как «ждёт ввода», и запрос из чата
  вставлялся в командную строку оболочки (найдено ревью).
- **Считать пунктом списка любую строку со знаком и номером.** Запрос с нумерованным списком
  в настоящей строке ввода Codex переставал отправляться (найдено повторным ревью);
  отличает их оформление знака.

## Известные ограничения

- Список Codex без номеров отличим от двухстрочного ввода только по оформлению: экран обязан
  сниматься с `-e`.
- Меню, которое красит указатель отдельно от пункта, прошло бы как строка ввода; среди
  снимков такого вида нет.
- Процесс `node` считается агентом у обоих (установка через npm), а «жив» определяется по
  существованию процесса, а не по переднему плану: остановленный агент и посторонний `node`
  в той же панели получат вставку.
- Диалог с вариантами без узнанной подсказки карточкой не становится — открывается окном
  терминала.
- Постановка сообщения в очередь Codex по Tab, пока в очереди ждёт вопрос, убирает вопрос —
  поведение самого Codex, чат его не обходит.
