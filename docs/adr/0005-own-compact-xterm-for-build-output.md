# 0005. У вкладки Gradle свой компактный xterm, а не `openTerminal`

## Контекст

Под списком тасок нужно живое терминальное окно с выводом сборки (R08, R09). В вебе
уже есть `openTerminal` из `term.ts` — рабочий терминал главного экрана.

## Решение

Вкладка монтирует собственный небольшой вид: xterm + FitAddon + `transport.openTerm`,
шапка со статусом и кнопками, ввод с клавиатуры проброшен в сборочную сессию.
`openTerminal` не переиспользуется и не рефакторится.

## Почему

`openTerminal` монтирует целый экран — полосу вкладок сессий, панель клавиш, подгонку
под экранную клавиатуру, ссылки на файлы; на вкладке Gradle всё это лишнее.

Отвергнут вариант вытащить из него «голый» терминал: это рефакторинг ~600 строк
рабочего кода ради одного нового потребителя, с риском задеть главный экран продукта.

Отвергнут и вариант «просто лог, без интерактива»: сборка иногда о чём-то спрашивает,
и ответить ей надо (A03 → R09), а значит нужен настоящий терминал с вводом.

## Последствия

Теперь xterm создаётся в двух местах: правку поведения терминала — тему, шрифт,
обработку ссылок, поведение при реконнекте — придётся вносить дважды или мириться с
расхождением между главным экраном и вкладкой Gradle.

Раскладка (55/45, перетаскиваемый разделитель, «развернуть» с запоминанием в
localStorage) — своя логика вкладки, она не наследуется от терминала сессии.

Если у «голого» терминала появится третий потребитель, отвергнутый здесь рефакторинг
стоит пересмотреть: аргумент «ради одного потребителя» перестанет действовать.
