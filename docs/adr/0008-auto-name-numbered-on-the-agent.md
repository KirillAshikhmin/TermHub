# 0008. Имя по умолчанию нумерует агент по признаку `autoName`, ответ несёт фактическое имя

## Контекст

Имя по умолчанию — санитизированное имя папки — веб и раньше слал агенту готовым;
второе создание для той же папки без имени падало на «duplicate session». Оба
транспорта (LAN и relay) ходят в один `SessionService.create`.

## Решение

Контракт создания расширяется двумя необязательными полями. Вход — `autoName?: boolean`
(«имя не вводили, оно взято из каталога»); выход — фактическое имя: `{ok, session}` в
`POST /api/sessions`, `CreateOk{session}` в relay, `create()` возвращает `{name}`. Веб
по-прежнему присылает готовое имя и ставит `autoName` ровно когда поле «Имя» пустое.
Агент при `autoName` берёт первое свободное из `база`, `база1`, `база2`… по сырому
`tmux list-sessions -F '#{session_name}'` (база обрезается, чтобы суффикс влез в 40),
а «duplicate session» от `new-session` перебирает дальше, не больше 5 попыток. Без
признака — прежнее поведение; введённое руками имя не трогается. Веб открывает имя из
ответа, без поля в ответе — запрошенное.

## Почему

Отвергнут подбор имени на клиенте — по списку сессий, который у веба и так есть: этот
список отфильтрован (`list()` прячет сборочные `_gradle_`-сессии, ADR 0002), приходит
поллингом и устаревает, а два устройства подобрали бы одно имя одновременно; к тому же
правило пришлось бы повторить в обеих формах диалога и держать паритет LAN/relay
руками. Отвергнут вариант, где агент сам выводит имя из каталога, а веб шлёт только
`dir`: у имени по умолчанию стало бы два источника — подсказка в поле и вывод на
агенте — и они разъехались бы на санитизации; поле `name` осталось бы обязательным
для старых клиентов, то есть отдельная ветка. Отвергнута нумерация всегда, включая
введённые руками имена: ручное имя значит «хочу ровно так», и молчаливое `MyProject1`
вместо запрошенного было бы сюрпризом; при нужде включается одной строкой — всегда
слать `autoName`. Отвергнута проверка занятости через `list()` вместо сырого
`list-sessions`: скрытая сборочная сессия числилась бы свободным именем, и
`new-session` падал бы; заодно `list()` делает лишний `list-panes`. Суффикс без
разделителя и без разбора цифр на конце базы (`v2` → `v21`, а не `v3`) — буквально
по брифу: сессия `v3` для папки `v2` вводила бы в заблуждение.

## Последствия

Поле `session` в ответе — теперь контракт, а не эхо запроса: клиент, открывающий
запрошенное имя, попадёт не в ту сессию. Старые пары совместимы, но не починены:
веб без признака по-прежнему получает ошибку на дубле. На каждое создание — лишний
`list-sessions`; гонка двух устройств закрыта на 5 попыток, дальше честная ошибка.
Автономера отбирают имена у соседей: папка, названная буквально `MyProject1`,
столкнётся с автономером `MyProject`. Санитизация у веба (`my.app` → `my_app`) и у
`tm` (`my.app` как есть) разная, семейства номеров у них свои — выравнивание отдельный
вопрос (ADR 0011). Алфавит и длина имени не ослабляются: кандидаты по построению
проходят `NAME_RE`, а `name` проверяется до всякого подбора.
