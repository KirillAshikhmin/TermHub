# 0032. Лента opencode: беседа из общей базы, привязка панели по рабочему каталогу

## Контекст

У Claude и Codex беседа — файл строк JSON, и панель к нему привязывается признаком самой
панели: адресом в реестре Claude или открытыми файлами процесса у Codex. У opencode (2.2)
не так. Все беседы всех каталогов лежат строками одной SQLite-базы
`~/.local/share/opencode/opencode.db` (`session_v2` — беседы, `session_message` — строки),
и пишет её общий фоновый сервер (`opencode serve --service`). TUI в панели — тонкий клиент:
ни файла беседы, ни базы он открытыми не держит, а беседу в аргументах не называет.
Замер 29.10.2026: TUI — один процесс `opencode` с рабочим каталогом проекта, базу держит
только сервер.

## Решение

Определитель узнаёт клиента opencode среди процессов панели (первое слово команды —
`opencode`, но не `opencode serve`), берёт его рабочий каталог и выбирает в базе корневую
неархивную беседу этого каталога, тронутую последней (позднейшее из `time_updated` и
`time_viewed`). Ответ — путь базы плюс идентификатор беседы (`session`).

Отказ вместо догадки в трёх случаях:
- в том же каталоге работает второй клиент opencode — `lookup-failed`;
- последнюю беседу каталога не трогали с запуска клиента — `no-transcript`: свежий TUI
  беседу ещё не начал, а вчерашняя — не его;
- в базе нет ожидаемых таблиц или столбцов — `unknown-format`.

Страницу собирает `readOpencodeFeed`: курсор — `<беседа>:<seq>`, `before` читает строки
строго до `seq`, `after` — начиная с него. Ответ модели, который ещё пишется, в конце беседы
в ленту не идёт, и курсор стоит перед ним — как перед недописанной строкой файла. База
открывается встроенным `node:sqlite` только на чтение и на один запрос.

## Почему

Каталог — единственный признак, который у клиента opencode снаружи вообще есть. Сам по себе
он беседы не различает, поэтому правило и отказывает ровно там, где различить нечем:
показать в панели беседу соседа хуже, чем не показать ничего.

Отвергнут вариант «спросить сервер opencode по HTTP» (адрес и пароль лежат в
`~/.config/opencode/service.json`). Он, возможно, точнее, но завязывает агента на
непубличный API чужого сервера, на его пароль и на то, что сервер запущен. База читается и
тогда, когда сервер лежит.

Отвергнут вариант «искать беседу по аргументам `--session`»: из пресета TermHub и из `tm`
клиент запускается без аргументов, и правило покрыло бы только ручной запуск.

Отвергнута зависимость `better-sqlite3`: нативный модуль ради чтения пары запросов, когда в
Node 22 есть `node:sqlite`.

## Последствия

Два opencode в одном каталоге ленты не дают вовсе, ни тому, ни другому.

Беседа, открытая из списка бесед TUI без новой реплики, видна, только если opencode обновил
у неё `time_viewed`; иначе до первой реплики лента говорит «беседы ещё нет».

Схема базы закрытая и меняется с версиями opencode (таблица уже называется `session_v2`). Её
смена приходит в ленту отказом `unknown-format`, а не мусором, но чинить чтение придётся
вслед за opencode.

`node:sqlite` в Node 22 помечен экспериментальным: при первом чтении базы в лог агента
падает одно предупреждение. Модуль грузится лениво, поэтому без opencode его нет.
