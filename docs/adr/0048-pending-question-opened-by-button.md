# 0048. Ожидающий вопрос Codex открывается кнопкой, и клавиша зависит от приглашения на экране

Дата: 12.11.2026. Статус: принято.

## Задача

Codex не всегда показывает вопрос сразу: он пишет, что вопрос ждёт, и предлагает нажать клавишу — Shift+← для очереди последующих вводов, Ctrl+/ для побочной беседы. Пользователь хочет видеть, что вопрос есть, и ответить из чата.

## Решение

Увидев приглашение, чат показывает над полем ввода кнопку «Вопрос агента», но клавишу сам не нажимает: клавиши в панель уходят только по действию человека. Нажатие шлёт агенту действие «показать вопрос»; какую клавишу нажимать, решает свежий экран на хосте (по тексту приглашения), а не клиент и не жёсткая константа. Когда вопрос открыт, он показан карточкой с вариантами, как обычный, а ответ сверяется отпечатком (ADR 0040). Если после клавиши экран остался прежним, ответ — `stale`.


## Отвергнуто

- **Открывать вопрос автоматически.** Нажатие клавиши в панели без человека меняет состояние агента (он может сменить режим, уйти в побочную беседу), пока человек работает в терминале; исключение для сверки команд (ADR 0042) уже единственное.
- **Одна фиксированная клавиша.** Приглашения разные: Shift+← и Ctrl+/ делают разное, и неверная клавиша ушла бы в другой экран.
- **Решать клавишу на клиенте по последнему состоянию.** Состояние устаревает, как и сам вопрос.

## Известные ограничения

- Человеку нужен один лишний тап, чтобы вопрос открылся.
- Любое новое приглашение Codex чат не открывает, пока в профиле нет для него клавиши.
