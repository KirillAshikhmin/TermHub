# 0047. Картинки по пути отдаёт существующий файловый сервис; гостю — только каталог его сессии

Дата: 12.11.2026. Статус: принято.

## Задача

Агент пишет в ответе путь снимка экрана или вложения. Пользователь хочет миниатюру в чате с просмотром по клику. Файл лежит на хосте, часто во временном каталоге агента, а не в корне проекта.

## Решение

Миниатюру отдаёт тот же файловый сервис, что обслуживает проводник, отдельным действием «картинка» на обоих транспортах; своего хранилища и копирования нет. Отдаются только файлы внутри корней сессий, каталога вложений TermHub и временного каталога агента, только настоящие картинки (по содержимому, не по имени) и не больше 20 МиБ; всё прочее остаётся обычным текстом в сообщении без ошибки. Гостю отдаётся лишь каталог его собственной сессии, а на любой другой случай — один и тот же отказ «картинка недоступна», по которому нельзя отличить «нет файла» от «нельзя». Владельцу временный каталог агента отдаётся целиком, со всеми сессиями этого пользователя на хосте (решение D05 манифеста): привязать этот каталог к одной сессии без определителя панели нечем, а владелец и так открыл эти каталоги в корнях.

## Отвергнуто

- **Копировать картинки в каталог TermHub при показе.** Дублирует файлы и сам становится общим каталогом, который гостю нельзя открывать.
- **Отдельный сервис картинок.** Второй список разрешённых путей, расходящийся с проводником, — место для обхода проверки.
- **Гостю общие каталоги тоже.** Временный каталог и каталог вложений общие для всех сессий хоста: гость увидел бы картинки чужих сессий.
- **Различать отказы.** «Нет файла» против «нельзя» выдаёт гостю существование чужих файлов.

## Известные ограничения

- Владелец через чат может открыть картинку любой своей сессии из временного каталога агента; это принятая цена D05, снимет её только привязка каталога к сессии.
- Гость миниатюр во временном каталоге не видит, даже если картинка относится к его сессии.
- Картинка читается с диска хоста по каждому показу; кэш — только в браузере.
