# 0011. `tm` без аргумента создаёт следующую по номеру сессию, а не присоединяется

## Контекст

`tm` — функция в rc-файле, которую печёт `termhub setup`: без аргумента `new -As` с
именем папки — присоединиться или создать. Пользователь снял «вне рамок»: нумерация
нужна и в `tm`, а агент в момент вызова может быть не запущен.

## Решение

`tm` без аргумента: база — `basename "$PWD"` как есть; пока кандидат занят (точное
совпадение со строкой `list-sessions -F '#{session_name}'`, ADR 0012) — следующий
`<база><n>`, n = 1, 2, …; затем `new -s <кандидат>` без `-A`. `tm <имя>` — по-прежнему
`new -As`, `tml` зовёт `tm "<имя>"`: это и есть путь «вернуться в свою сессию». POSIX
sh без `local`, одинаково в bash и zsh; нет сервера — имя свободно. Текст функции
строит `tmFunction(socket)`. `setup` при маркере `# termhub` без текущего определения
ищет старую однострочную `tm() { tmux … }` и предлагает заменить ровно её (`Update tm?
[Y/n]`); не распознал или отказ — печатает новое определение для ручной вставки
(чистый `upgradeTmFunction(existing) → string | null`).

## Почему

Отвергнут вариант оставить `-A` голому `tm`: второй `tm` в той же папке — снова та же
сессия, и «Claude в одной, оболочка в другой» из терминала IDE недостижимо без
выдумывания имён — ровно то, от чего избавляется бриф. Отвергнут «умный» вариант —
присоединяться к сессии папки, если к ней никто не подключён, иначе создавать новую:
признак «attached» ненадёжен (агент тоже держит `attach` для веба), а результат
команды зависел бы от невидимого состояния. Отвергнут вариант, где `tm` зовёт агента
или CLI `termhub`, чтобы правило жило в одном месте: агент в это время может быть не
запущен, а `tmux` под рукой всегда; цена — правило существует дважды, в TypeScript на
агенте и в POSIX sh. Отвергнута перезапись всего блока `# termhub` при обновлении:
пользователь мог править блок руками; заменяется только распознанная строка `tm`,
остальное — байт в байт. Отвергнут и отказ трогать старые блоки (только
документировать): у всех, кто уже прошёл `setup`, веб и шелл тихо нумеровали бы
по-разному. Гонку двух одновременных `tm` из разных терминалов сознательно не
закрываем: tmux ответит «duplicate session», повторный `tm` возьмёт следующий номер.

## Последствия

Изменение поведения, о котором надо сказать пользователю: голый `tm` больше не
возвращает в существующую сессию папки — после перезапуска IDE привычный `tm` даст
`MyProject1` вместо `MyProject`; вернуться — `tml` или `tm <имя>`. Одно правило в двух
реализациях, которые могут разъехаться и уже разошлись на базе: веб санитизирует
(`my.app` → `my_app`), `tm` берёт `basename` как есть — семейства номеров у них разные,
выравнивание — отдельный вопрос. Логика шелла проверяется подложным `tmux` в `PATH`,
а не живым attach (ему нужен tty) — то, чего в подложке нет, тест не увидит (ADR 0012).
Распознавание старого `tm` — регулярка на одну строку: правленное руками определение
останется нераспознанным, и обновление уйдёт в ручную вставку. README (en + ru)
описывают правило для обоих входов и обязаны меняться синхронно.
