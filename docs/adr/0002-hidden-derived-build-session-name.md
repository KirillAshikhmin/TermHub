# 0002. Имя сборочной сессии выводится из рабочей, сама она скрыта из списков

## Контекст

Сборка живёт в отдельной tmux-сессии (ADR 0001). Её надо снова найти после
перезагрузки страницы и не показывать пользователю среди его рабочих сессий.

## Решение

Имя — `_gradle_<санитизированное имя рабочей сессии, ≤24>_<6 hex от sha256 полного
имени>`. Сессии с префиксом `_gradle_` вычёркиваются из `SessionService.list()`;
attach на них при этом работает — WS-роут проверяет имя через
`isExistingSessionName`, а не через список. По завершении команды сборочная сессия
не убивается: в ней остаётся оболочка с выводом, а убирается она следующим запуском.

## Почему

Имя детерминировано, поэтому хранить состояние не нужно: после перезагрузки страницы
сборочная сессия находится вычислением имени. Отвергнут вариант хранить соответствие
«рабочая сессия → сборочная» где-то на диске или в памяти агента — это ещё один
формат состояния, который надо инвалидировать и переживать рестарт, ради того, что
и так выводится из имени. Хвост-хэш нужен потому, что обрезка длинных имён до 24
символов даёт коллизии, а полное имя не влезает в контракт `^[\w-]{1,40}$`.

Скрытие из `list()`: иначе сборочные сессии полезли бы в дашборд, в полосу вкладок и
в поллинг звонков. Отвергнут вариант показывать их наравне с рабочими — пользователь
получил бы дубли сессий, которых он не создавал.

Отвергнут вариант убивать сессию по завершении команды: вернувшийся пользователь
увидел бы пустой экран вместо итога сборки — ровно то, от чего защищает ADR 0001.

## Последствия

Сборочная сессия переживает и конец сборки, и перезапуск агента: оболочка с выводом
висит до следующего запуска, а вне вкладки убирается только руками через tmux.
Префикс `_gradle_` становится зарезервированным — рабочая сессия с таким именем
окажется невидимой в дашборде. Push-уведомление о завершении сборки этим решением
закрыто: сборочные сессии намеренно вне поллинга звонков, и уведомление придётся
делать отдельным решением, а не побочным эффектом.
