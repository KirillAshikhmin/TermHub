# Чат поверх терминала: разбор осуществимости

Задача: работать с Claude Code и Codex из веба TermHub как в приложении-чате, оставив за
ним родной инструмент в той же панели tmux. Чат читает экран панели и нажимает за человека
клавиши; переписка берётся из транскрипта на диске. Этот документ — замеры на живых агентах:
что из задуманного работает, чем это проверено и где хрупко.

Формы провода — `packages/protocol/src/chat.ts`, профили агентов —
`packages/agent/src/agent-profiles.ts`, распознавание экрана —
`packages/agent/src/agent-screen.ts`, снимки — `packages/agent/test/fixtures/screens/`.

## На чём мерили

| Что | Версия |
|---|---|
| Claude Code | 2.1.322 |
| Codex CLI | 0.167.0 (запуск пресетом TermHub: `-c tui.animations=false --no-alt-screen`) |
| tmux | 3.7c |
| ОС | macOS (Darwin 27) |

Замер 12.11.2026. Агенты запускались на отдельном сокете tmux (`-L termhub-probe-…`) во
временном каталоге, панель 100×32 (вопросы пересняты при ширине 50–60). Виды вопросов Codex
домерены тем же способом на Codex CLI 0.167.2 (панель 160×45, побочная беседа — 250 и 400
колонок; раздел «Вопросы Codex: домер»). Экран снимался
`capture-pane -p -e`, клавиши шли `send-keys` (в том числе `-H`), вставка — `paste-buffer -p`.
Рабочий сокет и сессии владельца не трогались.

## Экран

- **Claude работает в альтернативном буфере** (`alternate_on` = 1), и `capture-pane -p`
  отдаёт ровно видимый экран. Истории в панели нет (`capture-pane -S -` даёт те же 32 строки) —
  переписку с экрана не взять, только из транскрипта.
- **Codex с `--no-alt-screen` рисует в обычном буфере**; его интерфейс не прижат к низу панели:
  под подвалом бывают пустые строки. Разбор идёт от последней непустой строки.
- **Снимать надо с оформлением (`-e`).** Подсказку-заглушку в пустой строке ввода оба агента
  рисуют тусклым (`ESC[2m`): «Try "write a test for <filepath>"», «Ask Codex to do anything», у
  Claude ещё и предложенный следующий запрос, и «Press up to edit queued messages». Без
  оформления заглушка неотличима от набранного текста. В снимке с `-e` встречаются и гиперссылки
  `ESC]8;…` — разбор их выбрасывает.
- **Строка ввода Claude** стоит между двумя линейками `─`, под нижней — подвал с режимом. После
  знака `❯` в строке ввода стоит неразрывный пробел (U+00A0), в репликах человека выше —
  обычный.
- **Строка ввода Codex** — строка `› …`, пустая строка, подвал `модель уровень · каталог …`.
  Так же выглядят его меню («› 2. …», пустая, «enter select · esc back»), поэтому подвал
  проверяется: в подвале строки ввода нет слов `enter`/`esc`.
- **Подвал подменяется разовыми подсказками**: у Claude — «paste again to expand», у Codex при
  наборе во время работы — «tab to queue message … 97% context left». Режим и модель в такой
  момент с экрана не читаются; распознавание их не называет.
- **Перенос длинной строки неотличим от переноса строки в тексте**: и то и другое — новая
  строка экрана с отступом в два пробела. Текст строки ввода читается с точностью до этого.

## Ввод

- **Bracketed paste доходит одним запросом** у обоих. Работают оба способа: `load-buffer` +
  `paste-buffer -p` и прямая посылка `ESC[200~ … ESC[201~` через `send-keys -H`.
- Claude вставку из четырёх и более строк сворачивает в метку `[Pasted text #1 +3 lines]` —
  сам текст в строке ввода после этого не виден (три строки показал как есть).
- **Отправка — Enter (`\r`)** у обоих.
- **Перенос строки — `ESC` + `CR` одной посылкой** у обоих. У Codex те же два байта двумя
  посылками — это Esc и затем Enter, то есть отправка.
- **Стереть строку ввода**: Claude — два Esc подряд; Codex — Ctrl+C. Ctrl+U у обоих стирает
  только текущую строку экрана. Оба способа годятся ТОЛЬКО при непустой строке: на пустой два
  Esc у Claude открывают меню отката (Rewind), а Ctrl+C у Codex закрывает агента (проверено —
  Codex вышел).
- **Остановка — Esc** у обоих. Claude пишет «Interrupted · What should Claude do instead?»,
  Codex — «Conversation interrupted».

## Вопросы и разрешения

- **Цифра варианта отвечает сразу**, без Enter, у обоих агентов — и в вопросе, и в запросе
  разрешения, и в запросе Codex на инструмент MCP (подвал «enter to submit | esc to cancel»:
  проверено домером — цифра подтверждает сама, Enter после неё ушёл бы уже в следующий
  экран). Стрелки для выбора варианта не нужны.
- **Claude, вопрос (`AskUserQuestion`)**: заголовок, пронумерованные варианты с пояснением
  строкой ниже, затем «Type something.» (свой ответ) и за линейкой «Chat about this». Подвал
  «Enter to select · ↑/↓ to navigate · Esc to cancel».
- **Свой ответ у Claude**: цифра варианта «Type something.» ставит на него указатель, дальше
  текст набирается прямо в строке варианта, Enter отправляет. Подпись варианта при этом
  заменяется набранным — поэтому в отпечаток вопроса она не входит, а узнаётся вариант по
  месту (последний перед линейкой).
- **Несколько отметок у Claude**: варианты с `[ ]`/`[✔]`, цифра ставит и снимает отметку,
  стрелка вправо ведёт на экран «Review your answers … Ready to submit your answers?», там «1»
  отправляет. Этот экран распознаётся как вопрос с вариантами «Submit answers» и «Cancel».
- **Claude, разрешение**: «Do you want to create hello.txt?», варианты «Yes», «Yes, and switch
  to accept edits … for this session (shift+tab)», «No»; подвал «Esc to cancel · Tab to amend».
  Над вопросом — что агент хочет сделать (инструмент, файл, содержимое).
- **Codex, вопрос (`request_user_input`)**: «Question 1/1 (1 unanswered)», заголовок, варианты
  в две колонки (подпись и пояснение), последним «None of the above»; подвал «tab to add notes |
  enter to submit answer | esc to interrupt». Свой ответ у Codex — заметка по Tab (см. домер
  ниже).
- **Codex, разрешение**: «Would you like to run the following command?», окружение, причина,
  команда; варианты «Yes, proceed (y)», «Yes, and don't ask again for commands that start with
  … (p)», «No, and tell Codex what to do differently (esc)»; подвал «Press enter to confirm or
  esc to cancel».
- **Вопрос отличим от текста**: диалог узнаётся по подсказке в последних строках экрана, по
  вариантам, пронумерованным подряд с единицы, и по заголовку над ними. Нумерованный список в
  ответе агента диалогом не считается — под ним стоит строка ввода.
- **Отпечаток (`questionStamp`)** считается по заголовку и по клавишам с подписями вариантов,
  без пробелов и переносов: тот же вопрос при ширине 100 и 50–60 даёт тот же отпечаток
  (проверено снимками `*-narrow`).
- Без запроса разрешений замер у Codex не обошёлся: с настройкой «Approve for me» он не
  спрашивал вовсе; экран снят в режиме «только чтение» (`-s read-only`,
  `approvals_reviewer="user"`).

## Вопросы Codex: домер (0.167.2)

Codex запускался с доверием каталогу и своим пробным MCP-сервером через аргументы `-c`
(`projects={…}`, `mcp_servers.…`) — `~/.codex/config.toml` не менялся. С аргументами `-c`
Codex работает без общего фонового сервера («requires embedded mode»).

- **Пояснения вариантов.** `request_user_input` рисует подпись и пояснение в одной строке
  двумя колонками; в узкой панели пояснение переносится под свою колонку. Последним Codex
  сам добавляет «None of the above — Optionally, add details in notes (tab)».
- **Несколько отметок Codex не рисует.** В схеме `request_user_input` нет ни отметок, ни
  поля свободного текста (так ответил и сам Codex); вопрос «выбери несколько» приходит
  обычным вопросом с одним ответом.
- **Свой ответ — заметка.** Tab открывает под вариантами поле «› Add notes» (заглушка
  тусклым), подвал меняется на «tab or esc to clear notes | enter to submit answer»; текст
  набирается в поле, Enter отвечает: в переписке «answer: None of the above / note: …».
  Заметка идёт к варианту под указателем, поэтому сначала указатель ведётся стрелкой вниз
  до «None of the above» (стрелка двигает указатель на один вариант; цифра для этого не
  годится — она отвечает сразу). Повторный Tab поле закрывает.
- **Несколько вопросов в одном запросе.** «Question 1/2 (2 unanswered)», в подвале
  добавляется «←/→ to navigate questions»; цифра отвечает и ведёт к следующему вопросу, у
  последнего подвал — «enter to submit all», и цифра на нём отправляет всё. Свой ответ на
  таком запросе не измерен — чат его там не предлагает.
- **Ожидающий вопрос.** Вопрос главного потока Codex показывает сразу — и при набранном
  тексте в строке ввода (черновик возвращается после ответа), и после возврата из просмотра
  подагента. Не показывает он его в **побочной беседе** (`/side`, клавиша Ctrl+/): там в
  подвале стоит «Side from main thread · main needs input · ⌃/ to switch · ⌃c to close»,
  и Ctrl+/ возвращает в главный поток, где вопрос уже нарисован. Это и есть признак «вопрос
  ждёт» и клавиша открытия в профиле. Когда главный поток закончил, там же стоит «main
  finished» — это не вопрос.
- **Вопрос в очереди отложенного ввода («⇧← to answer»).** Замер таска 18 на Codex 0.167.2,
  панель 181×49. Кроме `request_user_input`, который останавливает ход и рисует вопрос
  сразу, у Codex есть `request_user_input_async`: вопрос задан, ход идёт дальше. Такой
  вопрос в переписке стоит строкой «? <вопрос>» со списком вариантов, а над строкой ввода,
  под строкой работы, появляется блок:

  ```
  • Queued follow-up inputs
    ? 1 question
      ⇧← to answer
  ```

  Строка счёта бывает «? 2 questions» и с таймером — «? 1 question · 20s»; строка
  приглашения нарисована тусклым. Воспроизводится запросом «задай вопрос через
  request_user_input_async и, не дожидаясь ответа, выполни `sleep 90`». Набранный текст в
  строке ввода и сообщение в очереди для этого не нужны. Строка работы при фоновой команде
  несёт приписку: «Working (24s • esc to interrupt) · 1 background terminal running · /ps to
  view · /stop to close».
  - **Признак в профиле** — `screen.pending` с блоком: заголовок с начала строки, под ним
    строка счёта и сразу за ней строка приглашения, и весь блок — последние непустые
    строки над строкой ввода. Те же слова в переписке признаком не считаются. Прочий
    отложенный ввод в том же блоке (строки без «? N question») — не вопрос.
  - **Клавиша** — Shift+← (`ESC [ 1 ; 2 D`), `keys.answerPending`; у побочной беседы своя —
    Ctrl+/ (`keys.showPending`). Какая уходит по `show-question`, решает приглашение,
    которое сейчас на экране.
  - **Экран после Shift+←** — на месте блока и строки ввода, под тем же заголовком:

    ```
    • Queued follow-up inputs

      Cats or dogs?

      › 1. Cats
        2. Dogs
        3. Other

      enter submit   ⌃] skip   ⇧→ main prompt
    ```

    Это отдельный вид диалога (не «Question 1/1» обычного вопроса): подвала строки ввода
    под ним нет. «Other» дописывает сам Codex. При двух вопросах над заголовком вопроса
    стоит «1 of 2», в подвале добавляется «⇧← next question», у последнего — «⇧→ prev
    question» вместо «⇧→ main prompt».
  - **Ответ.** Цифра варианта отвечает сама: в переписке появляется «↪ Re: <вопрос>» с
    ответом, блок исчезает (или открывается следующий вопрос очереди), Codex работает
    дальше. Цифра «Other» только ставит на него указатель; набранный текст заменяет
    подпись варианта, Enter отправляет его ответом. При указателе на пустом «Other»
    цифра существующего варианта — уже текст: «2» дало строку «› 3. 2», а «1 cup a day»
    одной посылкой — «› 3. 1 cup a day»; вариант при этом не выбирается и ничего не
    отправляется. Backspace возвращает подпись «Other».
  - **Отпечаток.** Счётчик «N of M» узнаётся только в этом диалоге и при M > 1 входит в
    отпечаток вопроса: два одинаковых вопроса подряд иначе неотличимы, и повторное нажатие
    ответило бы на второй невиданным. У одиночного вопроса очереди счётчика нет.
  - **Без ответа.** «⇧→ main prompt» (Shift+→) возвращает к строке ввода, блок с
    приглашением остаётся. «⌃] skip» (Ctrl+]) снимает вопрос из очереди без ответа. Esc
    на этом экране не нажимался — в подвале его нет, а у работающего Codex он прерывает ход.
  - **Не измерено:** вопрос без вариантов, несколько вопросов одним вызовом, прочие виды
    отложенного ввода в том же блоке и что по Shift+← открывается, когда вопрос в очереди
    не первый. Поэтому после клавиши чат принимает любой изменившийся экран: вопрос —
    показывает его, иной или неузнанный — отдаёт как есть (окошко терминала), без
    повторных и возвратных клавиш; приглашение осталось прежним — отказ `stale`. Переходы
    между вопросами очереди чат не нажимает: после ответа Codex сам открывает следующий.
- **Чего воспроизвести не удалось** (замер таска 16). Стрелка
  влево («← for agents») открывает «Agent command center» — список задач всех каталогов со
  счётчиком «Needs you»; Shift+← на экране главного потока без блока очереди ничего не
  меняет. Подагент
  задать вопрос не может вовсе («request_user_input can only be used by the root thread»),
  а запрос разрешения из подагента в пробной сессии не возник: команды оболочки там
  отваливались по сроку («timed out negotiating with the code-mode host») и в подагенте, и в
  главном потоке. При просмотре подагента (⌥←/⌥→, `/subagents`) подвал о вопросе главного
  потока не говорит. В строках бинаря есть «main needs approval», «parent needs input»,
  «Approval needed in …», «(needs approval)» — этих экранов замер не видел, и признаком они
  не считаются: такой экран чат покажет как обычно, а неузнанный — окошком терминала.
- **Запрос на инструмент MCP.** «Field 1/1», «Allow the <сервер> MCP server to run tool
  "<инструмент>"?», строка аргументов, четыре варианта с пояснениями, подвал «enter to
  submit | esc to cancel». Стрелки двигают указатель (счётчик при этом дописывает «(1
  required unanswered)»), цифра отвечает сама при любом положении указателя: «4» отменил
  вызов, «1» при указателе на втором варианте разрешил его. «Always allow» в замере не
  нажимался — он пишет настройки. Без `approvals_reviewer="user"` и пометки инструмента
  `destructiveHint` Codex вызвал инструмент без запроса.
- **Вопрос только со свободным ответом** (без вариантов) вызвать не удалось — не измерен.

## Серия вопросов Claude: полоса шагов

Над вопросом Claude рисует полосу «←  ☒ Название  ☐ Название  ✔ Submit  →»: отвеченный
вопрос помечен «☒», последний шаг — отправка, текущий шаг нарисован с фоном
(`48;5;153` на живых снимках `question-multi` и `question-review`). У одиночного вопроса
полоса — одно название. Чат показывает полосу над текстом вопроса с «N из M» и переходит
между шагами стрелками: вправо — измерено (так вопрос с отметками ведёт к экрану
подтверждения), влево — по стрелке «←» самой полосы и подсказке «Tab/Arrow keys to
navigate», живьём не измерено; после каждой клавиши экран обязан показать соседний шаг той
же полосы. Отпечаток вопроса серии несёт ещё и название текущего шага: вопросы серии
бывают с одним текстом и вариантами. Полоса из нескольких вопросов живьём не снималась —
снимки `question-series*` собраны из живых по их геометрии.

## Подсказки по «/»

- Список открывается над строкой ввода после «/» и сужается по мере набора.
- **Claude показывает 4–5 строк экрана** (две–четыре команды: длинная подсказка занимает две
  строки) независимо от свободного места; остальное — прокруткой стрелкой вниз. Всего в списке
  135 имён, из них около 80 встроенных команд, прочее — навыки и плагины пользователя.
  Подсказка длиннее двух строк обрезана «…».
- **Codex показывает 8 строк**, по одной команде в строке; всего 58 команд.
- Вывод для сверки списка с экраном: один снимок даёт только окно; полный список — это
  прокрутка на длину списка (у Claude ~140 нажатий, 0,12 с каждое).
- Встроенные команды обоих агентов занесены в профили с этих экранов.

## Режим

- **Claude**: Shift+Tab (`ESC[Z`) листает по кругу `manual → accept edits → plan → auto →
  manual`. Подвал называет режим: «⏸ manual mode on», «⏵⏵ accept edits on», «⏸ plan mode on»,
  «⏵⏵ auto mode on». Режим `auto` есть не у каждой учётной записи — круг тогда короче; цикл
  обязан сверяться с экраном после каждого нажатия.
- **Codex**: Shift+Tab переключает `Default ↔ Plan`; в подвале появляется «Plan mode», обычный
  режим подвал не называет. Смена режима меняет и уровень рассуждений («Model changed to
  gpt-6-astra medium for Plan mode»).
- Уровни разрешений Codex («Ask for approval», «Approve for me», «Full Access», «Read Only»)
  — отдельное меню `/permissions`, к режиму не относятся и из чата не переключаются.

## Модель

- **Claude**: `/model` открывает меню («Select model»: Default, Opus 5.5, Fable 5.2, Sonnet
  5.5, Haiku 5.5, More models). Enter в нём делает выбор **умолчанием для новых сессий**, клавиша
  `s` — только для этой сессии; затем подтверждение «Switch model?» (1 — да). После смены в
  переписке строка «Set model to Sonnet 5.5 for this session only». Текущую модель экран
  показывает только в шапке новой беседы; надёжный источник — поле `message.model` последнего
  ответа в транскрипте (обновится после следующего ответа).
- **Codex**: `/model` открывает меню «Select Model and Effort» (восемь моделей, затем уровень).
  Модель и уровень названы в подвале («GPT-6-Astra max») и в `turn_context.model` транскрипта.
- **Команда с именем модели (`/model <имя>`) не измерена**: смена модели пишет настройки
  агента, а менять их замеру запрещено. Идентификаторы моделей в профилях: у Codex подтверждён
  `gpt-6-astra` (транскрипт), остальные выведены из подписей меню; у Claude — привычные
  псевдонимы (`opus`, `sonnet`, `haiku`, `fable`), подтверждены только подписи.

## Контекст и расход

- **Claude**: занятость — `usage` последнего ответа в транскрипте (`input_tokens` +
  `cache_read_input_tokens` + `cache_creation_input_tokens`). Предела окна в транскрипте нет —
  доля в процентах для Claude не считается (прочерк).
- **Codex**: `event_msg` `token_count` несёт `info.last_token_usage` (занято) и
  `info.model_context_window` (предел, в замере 258 400); предел есть и в `session_meta`
  (`context_window`). На экране «97% context left» появляется только в подсказке при наборе во
  время работы — как источник не годится.

## Очередь

- **Claude**: сообщение, отправленное во время работы, встаёт над строкой работы строкой
  `❯ …` с подписью «ctrl+x ctrl+s to send now», в строке ввода — заглушка «Press up to edit
  queued messages». Числа агент не рисует; распознавание считает строки над подписью (замер —
  на одном сообщении). В транскрипте — записи `queue-operation` (`enqueue`, `dequeue`,
  `remove`, `popAll`).
- **Codex**: первое сообщение во время работы уходит в текущий ход сразу (появляется в
  переписке, «steer»), следующие встают в список «Messages to be submitted after next tool
  call» строками `↳ …` — их и считает распознавание. Esc прерывает ход и отправляет очередь.

## Вложения

- Вставленный путь **картинки** оба агента превращают во вложение (`[Image #N]`).
- Вставленный путь **не-картинки** (`.csv`) остаётся в строке текстом пути: вложением он не
  становится, агент прочтёт файл своим инструментом, если его об этом попросить. Вложение
  произвольного файла, значит, — это путь в тексте запроса.

## Что хрупко

- **Подвал Codex настраивается** (`/statusline`): распознавание строки ввода опирается на вид
  подвала «… · …». С другим составом подвала экран Codex будет не узнан — чат покажет окошко
  терминала.
- **Заголовок запроса разрешения Claude** берётся последним абзацем над вариантами; у Codex —
  абзацем, начинающимся с «Would you like to». Другая формулировка у Codex даст «не узнан».
- **Меню известны по заголовку**: четыре у каждого агента. Второй шаг меню модели Codex
  (уровень рассуждений) и прочие меню — «не узнан», то есть окошко терминала.
- **Анимации Codex выключены пресетом TermHub.** Сессия Codex, запущенная без
  `tui.animations=false`, рисует строку работы иначе — не измерено.
- **Тексты подсказок — английские и зашиты в агентов**; смена формулировок в новой версии
  ломает признаки. На это и рассчитан профиль: правятся данные и снимок.
- **Режимы Claude vim и `!`** (строка ввода начинается не с `❯`) — «не узнан».

## Не измерено

- `/model <имя>` и `/compact` с отправкой: первое меняет настройки агента, второе тратит
  токены на сжатие; команды есть в списках обоих агентов.
- У Codex: свой ответ на запрос из нескольких вопросов; вопрос без вариантов; экраны «main
  needs approval» и «parent needs …»; запрос разрешения из подагента; приглашение Shift+←.
- У Claude: полоса шагов из нескольких вопросов и стрелка влево по ней (см. раздел выше).
- Запрос разрешения Claude на команду оболочки: пробная команда прошла без запроса; снят
  запрос на запись файла.
- Очередь Claude из нескольких сообщений и многострочное сообщение в очереди у обоих.
- Два Esc одной посылкой у Claude (в замере шли раздельно, с паузой 0,3 с).
- Экраны при ширине панели меньше 50.

## Расхождения с намеченными границами

- `readScreen` нужны строки **с оформлением** (`capture-pane -p -e`), иначе заглушка в строке
  ввода читается как текст.
- Вставка текста работает и через `send-keys -H` с `ESC[200~…ESC[201~`, и через
  `load-buffer`/`paste-buffer -p`.
- В формах провода добавлены поля: `ScreenOption.free`, `ScreenState.menu`,
  `ScreenState.model`; свободный вариант входит в `options` и помечен.
- `questionStamp(title, options)` принимает заголовок и варианты, а не вопрос целиком.
- `ChatCommand.name` — без ведущего «/».
- Клавиша стирания строки ввода (`keys.clearInput`) — в профиле; действует только при
  непустой строке.
- Числа очереди Claude не рисует — `queued` считается по строкам; занятости контекста в
  процентах у Claude нет.
- Смена модели у обоих агентов идёт через меню, а не одной командой с именем.
