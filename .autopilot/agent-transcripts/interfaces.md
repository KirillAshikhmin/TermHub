# Границы и правила прогона

## Что строит прогон

Первый из трёх PR пути «лента агента из транскрипта»: определитель «панель → файлы
транскрипта». Без интерфейса, без чтения содержимого. Полноэкранный режим не трогаем —
он намеренно возвращён (ADR 0020).

## Правила проекта

- TypeScript strict, ESM, отступы 2 пробела. Комментарии по-русски и только там, где код
  не самоочевиден.
- Вызовы внешних программ — через `execFile` без shell (анти-RCE), как везде в проекте.
- Тесты tmux — только изолированный сокет `-L termhub-test-<уникальное>` с `kill-server`
  в teardown. Сокет `termhub` и дефолтный не трогать: на `termhub` живые сессии владельца.
- Секреты не логируются. Транскрипт содержит то же, что экран.
- Web не типизируется сборкой; этот прогон веб не трогает вовсе.
- Не хватает данных — возвращай BLOCKED, не выдумывай.

## Команды

```bash
npx vitest run packages/agent/test/                 # тесты агента
npm run build -w @termhub/agent                     # типы агента
```

Предсуществующая краснота вне зоны: `gradle.tmux.test.ts` (живые Gradle и tmux, около трёх
минут), `vcs.git.test.ts` (таймауты), `server.test.ts` (лимит 429). Мерить себя своим файлом.

## Решено пользователем и не подлежит пересмотру

1. Гость, допущенный к сессии, видит её ленту наравне (вопрос 1).
2. Лента панели — вся беседа, включая части до продолжения и форка; цена принята (вопрос 2).

## Что построили завершённые таски

**Таск 01 — определитель.** `packages/agent/src/agent-transcript.ts`: `resolve(pane, sources?)`,
`clearCache()`, шов `TranscriptSources` (home, socketName, readDir, readHead, isFile,
processTable, panePids, openFiles). Ответ — `{ok:true, agent, files:[файл], complete, live}`
или `{ok:false, reason, detail}`. Цепочки файлов нет (D01): продолжение и форк копируют
прежнюю беседу целиком, поэтому `files` — один файл.

**Таск 02 — общий вызов tmux.** `packages/agent/src/tmux-run.ts` (`runTmux`, `isNoServerError`,
`TmuxError`); `sessions.ts` и определитель ходят через него. `doctor.ts` остался со своим
`exec` — расхождение известно и не закрыто.

## Что изменила слепая приёмка 14.09.2026

Приёмка прогнала определитель по живым панелям владельца и нашла два неверных ответа; правки
внесены после закрытия ревью (коммит `fix(agent): see the agent a pane is attached to…`).

- Появился третий способ привязки: клиент `claude attach <id>` в панели. Фоновая сессия
  (`kind: "bg"`) записывает реестр БЕЗ поля `tmux`, и панель с таким клиентом отвечала
  «агента нет». Правило строгое: команда процесса `claude` И аргумент — начало ровно одной
  сессии реестра. Это единственное место, где модуль читает аргументы процесса.
- В `FailureReason` добавлена причина `no-transcript`: запущенная и ни разу не спрошенная
  сессия прежде получала `unknown-format`, то есть обвинение формата в отсутствии файла.
- Исчезнувшая панель отвечает `lookup-failed`, а не `no-agent`: «смотреть негде» и «в панели
  пусто» — разные ответы.
- Числа в комментариях приведены к свежему замеру: обход `lsof` — 0,05–1,5 с на панель
  вхолодную (не «0,4 с ровно»), дюжина панелей целиком — 0,8 с в прогоне `resolve`.
  Утверждение «все девять записей реестра мертвы» убрано: это была перепись одного дня,
  на следующий день живы все девять, и ветка `staleFits` на живых данных не срабатывает.
