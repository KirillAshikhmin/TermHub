# Спецификация: определитель «панель → транскрипт агента»

Режим: полуавтомат · глубина: максимальная. Первый из трёх PR пути «лента из транскрипта»
(см. `2026-09-13-brief.md`). Интерфейса в этом прогоне нет.

## Задача

История вывода агента недоступна: работающий Claude Code занимает полноэкранный режим, а у
того буфера истории нет. Запрет полноэкранного режима пробовали и отменили (ADR 0019, 0020):
рамка ввода становилась частью потока и уезжала при листании.

Но оба агента и так пишут полный транскрипт на диск. Значит история существует — её нужно
не отвоёвывать у терминала, а найти.

## Решение

Модуль в агенте, который по панели tmux находит файлы транскрипта запущенного в ней агента.
Ничего не читает из них по содержанию, ничего не показывает: только отвечает, чей это агент
и где лежит его беседа. Следующие два PR добавят чтение, ленту и экран.

## Depth pass

| Измерение | Решение |
|---|---|
| Первый запуск | Реестра или каталога сессий может не быть вовсе — это «агента нет», а не ошибка |
| Пусто | Панель с голой оболочкой: агент не найден, ответ отрицательный и однозначный |
| Неверный ввод | Битый JSON в реестре, отсутствующие поля, `tmux` в незнакомом формате — запись пропускается, причина различима |
| Отказ | Нет прав на чтение файла или каталога, недоступен обход открытых файлов — «определить не удалось», не «агента нет»: это разные ответы |
| Прерывание | Агент завершился между поиском и ответом — файл остаётся валидным, отвечаем как есть |
| Рост | Двенадцать панелей опрашиваются подряд: дорогой поиск у Codex кэшируется на панель, ключ включает pid и его время старта |
| Границы | Читаются только каталоги агентов текущего пользователя; путь из реестра проверяется на принадлежность им, иначе отказ |
| Последствия | Транскрипт содержит те же секреты, что экран: решение о хранении на устройстве принимается на третьем этапе, здесь только путь |

## Решения по реализации

### §1. Один модуль, два способа

`packages/agent/src/agent-transcript.ts`. Наружу: `resolve(pane)` возвращает либо описание
находки, либо причину отказа. В находке четыре вещи: вид агента, файл беседы, признак
полноты и признак живости.

**Полнота и живость — разные вопросы, и их нельзя подменять друг другом.** Полнота
отвечает «содержит ли файл беседу с начала»: у Claude это так всегда (`D01`), у Codex
вычисляется по ссылке на исходный поток. Живость отвечает «работает ли в панели тот, кто
это писал»: запись реестра переживает свой процесс, а адрес панели переиспользуется новым
сервером tmux, поэтому находка по мёртвой записи возможна и должна быть видна как таковая.
Внутри два независимых способа — по реестру и по открытым файлам, — каждый закрыт своей
функцией и проверяется отдельно.

**Почему так.** Способы не имеют ничего общего, кроме результата; общий код между ними был
бы выдуманным. Разные функции позволяют одному способу сломаться при обновлении агента, не
утащив второй.

### §2. Привязка только по адресу панели

Claude: поле `tmux` реестра сравнивается с адресом панели. Codex: список открытых файлов
процесса панели и его потомков. Ни заголовок, ни рабочий каталог, ни время файла в привязке
не участвуют.

**Почему так.** Замерено: заголовок пуст у двух из семи, каталог общий у восьми сессий,
время изменения одинаково у всех пишущих. Единственный различающий признак — адрес панели.

### §3. Отказ различим по причине

Три разных ответа: агента в панели нет; агент есть, но формат незнаком; определить не
удалось из-за прав или недоступного обхода. Пустая лента не отдаётся никогда.

**Почему так.** Следующий этап покажет это человеку. «Ленты нет» и «не смог посмотреть» —
разные сообщения, и подменять второе первым значит врать.

### §4. Полная беседа — это текущий файл, а не цепочка

Определитель отдаёт файл текущей сессии. Цепочка назад не собирается: она дала бы дубль.

**Почему так.** Пользователь выбрал полную беседу (вопрос 2), и сборка показала, как она
достигается на самом деле (`D01`). Продолжение сессии **копирует** беседу целиком: первые
метки времени прежнего и нового файла совпадают до миллисекунды. Связка на диске указывает
только вперёд — запись `continued-in` лежит в прежнем файле и называет новый; внутри нового
о родителе нет ничего. Значит текущий файл и есть вся беседа.

Признак полноты остаётся: если текущий файл найден не через реестр, а иным путём, и
уверенности в его начале нет, это видно в ответе. Идти назад по аргументам процесса не
нужно — то, ради чего это делалось, уже лежит в текущем файле.

### §5. Гость видит ленту наравне

Права на ленту следуют правам на сессию: допущен к сессии — видишь и её беседу.

**Почему так.** Решение пользователя (вопрос 1). Отмечено в документации: лента шире
экрана, в ней есть то, что с экрана уже ушло.

### §6. Дорогой поиск кэшируется

Результат для панели держится в памяти, ключ включает pid и время его старта, так что смена
процесса сбрасывает запись. Отрицательный ответ живёт по сроку, а не бессрочно:
идентификатор процесса оболочки не меняется, когда внутри неё запускают агента, и без срока
однажды сказанное «агента нет» держалось бы до перезапуска. Запись панели, пропавшей из
списка, выселяется.

**Почему так.** Замер: около 0,4 с на панель, двенадцать панелей дают пять секунд.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `agent-transcript` | поиском транскрипта по панели | `resolve(pane) -> Found \| Failure`, `clearCache()`; в находке — вид агента, файл, полнота, живость | два способа поиска, кэш со сроком, разбор реестра, снимок источников |

**Шов для тестов один:** `resolve` на подменённых источниках — реестре, списке открытых
файлов и файловой системе. Настоящие агенты в тестах не запускаются.
