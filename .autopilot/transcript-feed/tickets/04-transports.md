## Что должно заработать

Одна и та же страница ленты приходит обоими путями: `GET /api/feed?session=…` по LAN и
пара кадров `Feed`/`FeedResult` через relay. Тело одинаковое — различие только в транспорте.

Гость, допущенный к сессии, получает её ленту наравне с хозяином: право записи для этого не
нужно (лента ничего не меняет), право `files` — тоже (лента не даёт прочитать произвольный
путь). Но только **свою** сессию: проверка та же, что в `doList`/`doOpen`.

## Из брифа, дословно

> «Гость, допущенный к сессии, видит её ленту наравне с хозяином»

## Разделы спецификации

Истории 13, 18–20; Решения §9, §11.

## Критерии приёмки

- [ ] `FrameType.Feed = 46` и `FeedResult = 47`; payload запроса `{session, limit?, before?, after?, around?}`
- [ ] `GET /api/feed` и пара кадров отдают побайтово одинаковый JSON при одинаковом запросе
- [ ] Гость со `scope` получает ленту своей сессии без права `write` и без права `files`
- [ ] Гость, спросивший чужую сессию, получает отказ той же проверкой, что и в `doOpen`
- [ ] Через ленту нельзя ни писать в сессию, ни читать произвольный файл: адресация только по имени сессии
- [ ] LAN-маршрут под той же cookie-авторизацией и проверкой Origin, что остальные `/api/*`
