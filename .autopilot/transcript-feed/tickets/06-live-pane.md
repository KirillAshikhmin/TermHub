# 06 — Активная панель находится на живом tmux

**Требования:** R09, R13i
**Blocked by:** 03
**Зона:** `packages/agent/src/session-feed.ts`, `packages/agent/test/session-feed.tmux.test.ts`
**Волна:** 4
**Status:** ready

Нарезан по находке слепой приёмки: на живых данных лента не отдаётся **ни по одной из
12 сессий владельца**.

## Что должно заработать

`sessionFeed('SprutApp')` на живом сокете `termhub` возвращает записи беседы, а не
`lookup-failed: has no active pane`.

Причина найдена и воспроизведена: `display-message -p -t '=SprutApp'` на tmux 3.7b отвечает
строкой `:.` — пустой формат, — потому что цель без двоеточия сессией не считается.
`-t '=SprutApp:'` отвечает `SprutApp:@0.%0`.

Тесты этого не поймали, потому что в `session-feed.test.ts` источник `activePane` подменён
всегда, а теста на настоящем tmux у модуля нет вовсе.

## Из брифа, дословно

> «Лента берётся не с экрана, а из транскрипта, который агент и так пишет на диск»

## Критерии приёмки

- [ ] `sessionFeed` по имени живой сессии возвращает страницу ленты, а не отказ
- [ ] Есть тест на **настоящем** tmux (свой изолированный сокет, своя уборка): сессия создаётся, панель находится, адрес имеет вид `сессия:@окно.%панель`
- [ ] Тест краснеет при возврате к цели без двоеточия
- [ ] Рабочий сокет `termhub` не тронут ничем: ни `send-keys`, ни новых сессий, ни завершения чужих
- [ ] Комментарий в шапке модуля не утверждает, что панель ищется «тем же вызовом, что и везде»: `session-link.ts` зовёт `display-message -p` без `-t`, из контекста подключённой панели, и это другой вызов
