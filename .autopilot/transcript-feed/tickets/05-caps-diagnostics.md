# 05 — Диагностика возможностей не врёт

**Требования:** R05, R06
**Blocked by:** 02
**Зона:** `packages/agent/src/relay-link.ts`, `packages/web/src/remote.ts`, тесты возможностей
**Волна:** 4
**Status:** ready

Нарезан не из спецификации, а из разбора отложенных находок ревью (этап «Приёмка»,
`state.js` → `concerns`). Три находки в одном месте, каждая — про то, что диагностика
показывает не то, что есть.

## Что должно заработать

`/api/diag` показывает пересечение возможностей с тем, кто подключён **сейчас**. Сегодня
счёт в relay не гаснет ни при уходе клиента, ни при обрыве связи, поэтому в диагностике
может стоять пересечение с устройством, которого давно нет, — и оно по времени перебивает
свежий обмен по LAN. ADR 0018 завёл эту строку ровно затем, чтобы «надстройка промолчала»
и «надстройка сломалась» различались; показывая призрака, она перестаёт их различать.

## Из брифа, дословно

> «Совместимость агента и PWA — через объявление возможностей (ADR 0018)»

## Критерии приёмки

- [ ] Пересечение в relay гаснет при уходе клиента и при обрыве связи с relay; `/api/diag` после этого не показывает ушедшего
- [ ] Тест краснеет, если счёт снова начнёт переживать клиента
- [ ] Комментарий в `packages/web/src/remote.ts` описывает фактическое поведение обмена (он мемоизирован на транспорт и гаснет сменой транспорта и потерей потока) — либо повторный `online` действительно инициирует новый обмен
- [ ] Утверждения тестов проверяют членство `feed` в пересечении, а не точный состав `AGENT_CAPS`; точный состав утверждается только там, где он и есть контракт этапа
