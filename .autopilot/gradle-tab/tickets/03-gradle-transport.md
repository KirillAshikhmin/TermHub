## Что должно заработать

Веб может спросить агента про Gradle и запустить сборку одинаково по LAN и через
relay — тем же способом, каким уже сделаны `repo` и `fileOp`. Гость с расшаренной
сессией получает ровно те права, которые ему выдали, и ни каплей больше.

(Функция обязана работать в обоих режимах TermHub — иначе она есть только дома.)

## Критерии приёмки

- [ ] `POST /api/gradle` принимает `{action, session, …}` и отвечает JSON по контракту из `interfaces.md`; неизвестный `action` → 400, а не 500
- [ ] Папка проекта берётся из пути сессии и проверяется realpath на вхождение в whitelist корней (как в `files.ts`); выход за корень → отказ
- [ ] Relay: фреймы `Gradle` / `GradleResult` обрабатываются в `relay-link.ts` тем же кодом, что и HTTP-роут (общая функция, не вторая реализация)
- [ ] `Transport.gradle<T>(action, params)` объявлен в интерфейсе и реализован в LAN- и relay-транспорте
- [ ] Гость со `scope`: `detect`/`tasks`/`configs` — только при `scope.files`; `run`/`stop` — только при `scope.write`; запрос про ЧУЖУЮ сессию отвергается
- [ ] Гость может подключиться терминалом к сборочной сессии СВОЕЙ расшаренной сессии и не может — к чужой
- [ ] Тесты: права гостя (все четыре комбинации scope), отказ по выходу за корень, неизвестный action
- [ ] `npx vitest run` зелёный целиком; `packages/agent/test/e2e.full.test.ts` проходит
