# Спецификация: вкладка Gradle на экране сессии

## Задача

Сессия TermHub открыта в папке Gradle-проекта. Чтобы собрать проект или прогнать
тесты с телефона, приходится вспоминать точное имя таски и печатать
`./gradlew :app:assembleDebug` на экранной клавиатуре — с двоеточиями, без
автодополнения, вслепую. В IDEA это два клика по панели Gradle. Хочется того же:
видеть, что вообще можно запустить в этом проекте, ткнуть — и смотреть, как идёт
сборка, не уходя с экрана.

## Решение

На экране сессии появляется четвёртая вкладка — **Gradle**. Она есть только у тех
сессий, чья папка действительно Gradle-проект; у остальных её просто нет.

Сверху — то же, что в панели Gradle у IDEA: конфигурации запуска проекта
(из `.run/` и `.idea/runConfigurations/`) отдельным списком, ниже — все таски,
сгруппированные по модулям и группам (build, verification, help…), с поиском и
недавними запусками. Снизу — терминальное окно: нажал «Запустить» — и в нём
живой вывод Gradle, как если бы ты сам набрал команду в терминале.

Сборка идёт в собственной tmux-сессии на стороне Mac. Поэтому её вывод не
пропадает, если переключиться на «Терминал», перезагрузить страницу, потерять
связь или закрыть телефон: вернулся — сборка либо всё ещё идёт, либо на экране
её итог. Кнопка «Стоп» прерывает её, как Ctrl+C.

## Решения по реализации

**§1. Сборка идёт в отдельной tmux-сессии, а не в процессе агента.**
Требование «вывод не теряется» (R13i) — это ровно то, что tmux уже умеет, и весь
продукт на нём стоит. Сборочная сессия создаётся на том же сокете `-L termhub`
(`config.TMUX_SOCKET`), вывод отдаётся существующим `openTerm` — значит LAN и relay
получают его бесплатно и одинаково (R14i), а reconnect/backoff уже написан.
Альтернатива (spawn + свой WS-канал + свой кольцевой буфер + свой фрейм в relay)
дороже втрое и хуже переживает обрыв.

**§2. Имя сборочной сессии — производное от имени рабочей, и скрыто из списков.**
`_gradle_<санитизированное имя, ≤24>_<6 hex от sha256 полного имени>` — детерминировано
(после перезагрузки страницы находится без хранения состояния), укладывается в
контракт `^[\w-]{1,40}$`, не сталкивается при обрезке. Сессии с префиксом `_gradle_`
вычёркиваются из `SessionService.list()` — иначе они полезли бы в дашборд, в полосу
вкладок и в поллинг звонков. Attach на них при этом работает: WS-роут проверяет имя
через `isExistingSessionName`, а не через список.

**§3. Команда отправляется через `send-keys`, а не как аргумент `new-session`.**
tmux запускает `shell-command` через `/bin/sh -c`, без профиля пользователя — а
Gradle почти всегда зависит от `JAVA_HOME` / sdkman / asdf, которые живут в
`~/.zshrc`. Поэтому: `new-session -d` без команды (tmux поднимает login-оболочку) →
`send-keys -l "<строка>"` → `send-keys Enter`. Каждый токен строки перед этим
валидируется отдельно (см. §7), так что метасимволов оболочки в ней быть не может.
Тем же путём идёт «Стоп»: `send-keys C-c`.

Цель для `send-keys` пишется как `=<имя>:` (с двоеточием), а не `=<имя>`: у команд,
принимающих target-pane, форма без двоеточия трактуется как имя ПАНЕЛИ и не находится
(проверено на tmux 3.7b). Префикс `=` при этом обязателен — он выключает поиск по
префиксу имени.

Строка собирается ровно так и в этом порядке:
`<./gradlew | gradle> <таска…> <аргумент…>; printf '\n[termhub] gradle exit=%s\n' $?`
— таски в том порядке, в каком их выбрали (или в каком они перечислены в
конфигурации), затем аргументы (из поля аргументов, куда уже подставлены
`scriptParameters` конфигурации). Флагов консоли от себя не добавляем: в настоящем
терминале уместен обычный богатый вывод Gradle, а `--console=plain` пользователь при
желании впишет в аргументы. Хвост с `printf` — единственное, что дописывается всегда:
без него код выхода не увидеть, сессия ведь остаётся в оболочке.

**§4. Список тасков — `gradle tasks --all`, распарсенный, с кэшем в памяти агента.**
Другого способа узнать таски снаружи IDEA нет (Tooling API — это JVM-зависимость,
которой в проекте не будет). Вызов идёт через login-оболочку (`$SHELL -lc` с
константной строкой, без интерполяции — cwd задаёт папку проекта), таймаут 180 с,
`--console=plain -q`. Результат кэшируется по (папка проекта → mtime build-файлов);
кнопка «Обновить» сбрасывает кэш. Дисковый кэш не заводим: экономит секунды раз в
запуск агента, а стоит ещё одного формата файла и его инвалидации.

**§5. Конфигурации читаются из XML узким парсером, без новой зависимости.**
Нужны ровно четыре поля из `<configuration type="GradleRunConfiguration">`: `name`,
`taskNames`, `scriptParameters`, `externalProjectPath`. Полноценный XML-парсер ради
этого тянуть не стоит (в проекте нет ни одного, и стиль — минимум зависимостей).
Читаются три источника: `.run/*.xml`, `.idea/runConfigurations/*.xml` и узел
`<component name="RunManager">` внутри `.idea/workspace.xml` — последний потому, что
конфигурация, созданная в IDEA и не «расшаренная» руками, лежит только там, а
пользователь видит её в списке наравне с остальными. Формат `<configuration>` во всех
трёх одинаков, парсер один. Дубли по имени схлопываются, файл из `.run` важнее.
Ограничения: не более 100 файлов, не более 256 КБ на файл (для `workspace.xml` — 4 МБ),
битый файл пропускается.

**§6. Какой Gradle запускается — и на каком JDK.** `./gradlew`, если он есть в
корне проекта и исполняем, иначе `gradle` из PATH login-оболочки, иначе запуск
заблокирован с объяснением (R07.3). Wrapper первым — так делает и IDEA, и это
единственный вариант, воспроизводящий сборку проекта.

*Исправлено после таска 05 (см. `D01` в манифесте).* Одного wrapper'а мало: он
исполняется на том JDK, который назвал `JAVA_HOME` login-оболочки, а у типичного
Android-проекта это не тот JDK. Проверено на живом проекте 2026-08-22:
`JAVA_HOME` пользователя — JDK 25, wrapper проекта — Gradle 8.9, и `tasks --all`
падает с «Unsupported class file major version 69»; с JDK, записанным в самом
проекте, тот же вызов отрабатывает. Поэтому JDK выбирается так же, как его
выбирает IDEA, в порядке: `org.gradle.java.home` из `<проект>/gradle.properties`
→ то же из `~/.gradle/gradle.properties` → `java.home` из
`<проект>/.gradle/config.properties` (это и есть `#GRADLE_LOCAL_JAVA_HOME`,
на который ссылается `.idea/gradle.xml`) → окружение login-оболочки как раньше.
Выбранный JDK передаётся и в получение списка тасок, и в запуск сборки.

**§7. Безопасность — по правилам, уже принятым в проекте.** Все вызовы tmux — через
`execFile` без оболочки. Имя таски проверяется регуляркой `^[A-Za-z0-9:._\-]{1,200}$`,
аргументы — `^[A-Za-z0-9:._=,\/@+\-]{1,200}$` каждый, не более 32 аргументов; всё,
что не прошло, отвергается с ошибкой, а не экранируется. Папка проекта — корень
сессии, проверенный через realpath на вхождение в whitelist корней (как в `files.ts`).
Права гостя: `scope.files` на чтение списка, `scope.write` на запуск и стоп.

**§8. Вкладка вывода — свой компактный xterm, а не `openTerminal` из `term.ts`.**
`openTerminal` монтирует целый экран: полосу вкладок сессий, панель клавиш,
подгонку под клавиатуру, ссылки на файлы. Вытаскивать из него «голый» терминал —
рефакторинг 600 строк рабочего кода ради одного нового потребителя. Вместо этого —
маленький собственный вид (xterm + FitAddon + `transport.openTerm`), ввод с
клавиатуры проброшен (сборка иногда спрашивает), плюс шапка со статусом и кнопками.

**§9. Ответы агента — новый экшен `gradle`, зеркально `repo`/`fileOp`.**
LAN: `POST /api/gradle`; relay: пара фреймов `Gradle = 41` / `GradleResult = 42`.
Один экшен с параметром `action` (`detect` | `tasks` | `configs` | `run` | `stop` |
`status`) — так уже сделано для VCS и файловых операций, второй способ делать то же
самое проект бы не улучшил.

**Швы для тестов** (их три, все — существующего вида):

1. `agent/gradle.ts` — чистые функции без tmux и без Gradle: `parseTasksOutput`,
   `parseRunConfigXml`, `detectProject` (на временном каталоге), `buildSessionName`,
   валидация запроса. Здесь же — основной объём проверок.
2. Изолированный tmux-сокет `-L termhub-test-<uniq>` (как в существующих тестах
   сессий) — `startRun`/`stopRun`/`runStatus` на команде-пустышке вместо Gradle,
   и фильтрация сборочных сессий из `list()`.
3. `web/gradle-view.ts` — чистые рендеры и группировка, без DOM-монтирования экрана.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| Push-уведомление о завершении сборки | сборочные сессии намеренно исключены из поллинга звонков (§2); нормальное уведомление — это отдельное решение (по каким событиям, как выключается), отдельный заход |
| Не-Gradle конфигурации IDEA (Application, JUnit, Android) | сужение требования R05 «все достепные конфигурации» — решение пользователя (вопрос 1, G02): «их без IDEA не запустить». Не наше решение и не молчаливое |
| Выбор build variant / устройства для Android | в брифе нет; вариант задаётся именем таски (`assembleDebug`) и аргументами |
| Несколько одновременных сборок в одной сессии | одна сборочная сессия на сессию — иначе нужен список запусков, свой роутинг вывода и своя модель состояния |
| Дерево тасков с точной типизацией через Gradle Tooling API | требует JVM-зависимости; текстового вывода `tasks --all` хватает для всего, что просил бриф |
