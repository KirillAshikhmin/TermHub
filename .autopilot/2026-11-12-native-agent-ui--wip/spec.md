# Спецификация: чат — нативный интерфейс к Claude и Codex поверх терминала

## Задача

Я работаю с Claude Code и Codex с телефона и из браузера через TermHub. Агенты живут в
терминале: отвечать на «1. Yes 2. No» приходится стрелками, длинный запрос набирается
вслепую в чужой рамке, переписка — моноширинный экран, который у Claude ещё и не листается.
Я хочу работать с ними как в обычном приложении-чате, но чтобы за ним стоял тот же родной
инструмент в той же сессии tmux, а не его переписанная копия. Понимаю, что обновление агента
может это сломать, — поэтому терминал всегда должен оставаться в одном нажатии.

## Решение

Вкладка «Лента» становится **чатом**. В нём: переписка с оформлением (заголовки, списки,
код, таблицы, ссылки и пути), действия агента строкой с раскрытием команды, вывода и diff;
своё поле ввода с черновиком, вложениями, подсказками слэш-команд и файлов; вопросы агента и
запросы разрешений кнопками; полоса состояния — что агент делает, остановка, режим, модель,
контекст и расход. То, чего чат не узнал на экране агента, открывается живым окошком
терминала прямо в чате. На вкладке терминала — переключатель вида; сессия с Claude или Codex
открывается чатом, остальные — терминалом, выбор помнится по сессии.

Переписка читается из транскрипта агента на диске (как лента сегодня), живое состояние — с
экрана панели tmux. Агент остаётся процессом в панели: чат только нажимает за человека
клавиши и читает экран.

Первым делом — разбор осуществимости с замерами на живых Claude и Codex: документ с
вердиктом по каждой части и снимки экранов, на которых дальше проверяется распознавание.

## Решения по реализации

- **Чат растёт из ленты, а не рядом с ней.** Экран ленты остаётся частью переписки; чат
  добавляет вокруг поле, полосу состояния, карточку вопроса и окошко терминала. Почему: поиск,
  подкачка и прыжки уже работают и проверены.
- **Живое состояние — отдельный запрос «экран панели», опросом раз в секунду** при открытом
  и видимом чате; изменение состояния сразу тянет приращение переписки. Почему: тот же приём,
  что у ленты (ADR 0028), и не требует открытого терминального канала.
- **Экран читается одноразовым `capture-pane`, клавиши шлются `send-keys -H`** мимо
  терминального подключения. Почему: чат не должен становиться клиентом tmux и влиять на
  размер окна.
- **Распознавание — чистая функция над строками экрана и профилем-данными.** Почему:
  проверяется на снимках без tmux; обновление агента чинится данными.
- **Любое действие сверяется с экраном перед отправкой клавиш.** Ответ несёт отпечаток
  вопроса; агент TermHub перечитывает экран и шлёт клавиши, только если отпечаток совпал.
  Почему: агент меняет файлы, клавиши по устаревшей картинке недопустимы.
- **Запрос с переносами вставляется как bracketed paste, затем клавиша отправки из профиля.**
  Почему: иначе перенос строки агент примет за отправку.
- **Подробности действия грузятся отдельным запросом по курсору записи.** Почему: страница
  ленты остаётся в пределе 1 МиБ.
- **Список команд собирает агент TermHub**: встроенные из профиля, пользовательские и
  проектные — с диска; сверка с экраном — один раз на версию агента, результат хранится на
  хосте. Файлы для «@» — существующим списком каталога проводника.
- **Режим** переключается клавишей цикла из профиля до нужного, с проверкой экраном после
  каждого нажатия, не больше числа режимов в профиле. **Модель и сжатие** — командами агента
  из профиля.
- **Занятость контекста** считается из последнего ответа в транскрипте (расширение расхода): у Claude — `usage` последнего ответа, у Codex — из `token_count`, если замер подтвердит, что там есть занятость и предел; иначе прочерк.
- **Вложения** — прежнее хранилище вставок, расширенное на произвольные файлы; предел 50 МиБ.
- **Выбор вида и счётчик сбоев живут на устройстве** (`localStorage`). Почему: через relay
  диагностики агента нет, а выбор вида — привычка устройства.
- **Провод:** три пары кадров с корреляцией по `id` и три маршрута LAN; возможность `chat`.
  Номера — в `interfaces.md`.
- **Деплой после каждого таска** — по процедуре из `CLAUDE.md` (выбор пользователя).
- Решения записываются ADR с номера 0038.
