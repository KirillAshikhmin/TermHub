# 02 — Веб: «имя не вводили» → `autoName`, переход на созданную сессию без отката

**Требования:** R02, R06i, R06i.1, R07i, R11, R11.1, R11.2, R12
**Blocked by:** —
**Зона:** `packages/web/src/api.ts` · `transport.ts` · `relay-transport.ts` · `dashboard.ts` · `ui.ts` · `routes.ts` · строки вызова `openCreateModal` в `files.ts`, `repo.ts`, `gradle.ts`, `term.ts` · `packages/web/test/`
**Волна:** 1
**Status:** ready

## Что должно заработать

В диалоге «Новая сессия» поле «Имя» пустое (подсказка — имя папки). Оставил пустым →
запрос уходит с `autoName: true`, агент подбирает свободное имя, и приложение открывает
именно созданную сессию (`MyProject1`), а не запрошенную. Ввёл имя руками → `autoName`
не ставится, поведение прежнее. Главное: после «Создать» экран **остаётся** на новой
сессии — сегодня он откатывается на старую, потому что модалка закрывается через
`history.back()` (асинхронно), а навигация ставит hash синхронно, и отложенный «назад»
возвращает на запись модалки со старым URL. Модалка должна закрываться «в сторону»
маршрута: заменить свою history-запись новой сессией. «Назад» из новой сессии — одним
нажатием туда, откуда нажали «+»; «Назад» на открытой модалке — просто закрывает её.
Гипотеза «вкладки ещё нет» опровергнута: полоса рисует текущую сессию активной сразу.

## Из брифа, дословно

> «допустим папка MyProject, создали сессию не вводя имя»
> «веб должен переходит на новую сессию, но вкладка только создаётся, но не переключается на неё, хотя должен. вероятно на момент переключения вкладки ещё нет, но проверь.»

## Критерии приёмки

- [ ] `CreateSessionInput.autoName?: boolean`; обе формы модалки (список каталогов и ручная) шлют `autoName: true` ровно когда поле «Имя» после `trim()` пустое; иначе признак не ставится
- [ ] `Transport.create(req): Promise<string>` в интерфейсе и обеих реализациях: LAN — `session` из ответа `POST /api/sessions`, при отсутствии — `req.name`; relay — `CreateOk.session`, при отсутствии — запрошенное имя (ожидающий `pendingCreate` помнит его). Тесты relay-transport: `{session:'x1'}` → `'x1'`; без поля → `'x'`
- [ ] `routes.termHash(name)` — единственный источник формата `#/term/<имя>`; `openCreateModal(transport)` без колбэка, навигирует сам; все пять вызовов обновлены (dashboard FAB, files, repo, gradle, term)
- [ ] `openModal`: `close(next?: string)` — с `next` делает `cleanup()` и `location.replace(next)` (без `history.back()`); без `next` — как раньше; `popstate` («Назад» на модалке) — как раньше только `cleanup`
- [ ] Тест модалки создания (happy-dom, транспорт-заглушка по образцу `dashboard-relay.test.ts`): после создания `location.hash === termHash(созданное)`, `history.back` не вызывался (spy), `history.length` не вырос относительно момента до открытия; «Отмена»/крестик → `history.back()` вызван
- [ ] Тест: пустое поле → `create` получил `autoName: true`; введённое имя → без `autoName`; навигация — на имя, которое вернул транспорт, а не на запрошенное
- [ ] Ошибка создания показывается тостом как раньше; кнопка возвращается в исходное состояние
- [ ] `npx tsc -p packages/web/tsconfig.json --noEmit` — без новых ошибок (известная предсуществующая в relay-transport — не считается); тест i18n зелёный (новых ключей нет); `npx vitest run` зелёный
- [ ] У `close(next)` — комментарий по-русски, объясняющий гонку `history.back()` против синхронной смены hash (это причина бага R11)
