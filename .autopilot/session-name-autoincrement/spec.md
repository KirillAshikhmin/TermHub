# Спецификация: уникальное имя сессии по папке с автоинкрементом — и три бага экрана сессии

## Задача

Я открываю TermHub с телефона, жму «+», выбираю папку `MyProject` и, не вводя имя,
жму «Создать». Первый раз всё хорошо. Второй раз для той же папки — ошибка
«duplicate session», потому что имя сессии по умолчанию совпадает с именем папки,
а такая сессия уже есть. Приходится придумывать и набирать имя руками — на телефоне
это раздражает, а именно вторая-третья сессия на один проект и нужна чаще всего
(Claude в одной, оболочка в другой).

И рядом три вещи, которые мешают каждый день. Создал сессию — экран остаётся на
старой, новая вкладка лишь появляется в полосе. Переключился на вкладку — печатаю,
а буквы уходят в никуда, пока не ткну в терминал. Нажал Enter — в Claude Code
сначала вставляется перевод строки и тут же уходит команда, в каком бы положении ни
стоял тумблер «Отправлять по Enter».

## Решение

Если имя не вводили, приложение само берёт имя папки, а когда оно занято — добавляет
номер: `MyProject` → `MyProject1` → `MyProject2` и так далее, до первого свободного.
Ошибки нет, после создания открывается именно та сессия, что получилась (в шапке
терминала видно `MyProject1`). Имя, введённое руками, приложение не трогает: оно
означает «хочу ровно так», и коллизия остаётся ошибкой, как сегодня.

Работает одинаково в LAN и через relay: правило живёт на агенте, где и есть
настоящий список сессий. То же правило получает `tm` в терминале IDE: `tm` без
аргумента в папке `MyProject` при занятом имени создаёт `MyProject1`; вернуться в
существующую сессию — `tml` или `tm MyProject`.

После создания экран переходит в новую сессию — сразу и надёжно, без отката на
старую. При переключении вкладок курсор оказывается в терминале, и набранное
доходит до него, даже если соединение ещё устанавливается. Enter делает ровно одно:
отправляет (тумблер включён) или переносит строку (тумблер выключен или зажат Shift).

Причины найдены по коду и подтверждены в живом Chrome, а не приняты на веру:
гипотеза «на момент переключения вкладки ещё нет» не подтвердилась — полоса
вкладок рисует текущую сессию активной сразу, независимо от списка.

## Решения по реализации

1. **Правило живёт на агенте, в `SessionService.create`.** Только у агента есть
   живой список сессий, и оба транспорта уже ходят в один метод — паритет LAN/relay
   получается сам собой, а гонка между проверкой и созданием закрывается там же, где
   создаётся сессия.

2. **Контракт создания расширяется двумя необязательными полями.** Вход:
   `autoName?: boolean` — «имя не вводили, оно взято из каталога; если занято —
   подобрать свободное с числовым суффиксом». Выход: фактическое имя. Веб продолжает
   присылать готовое имя (санитизированное имя каталога), агент лишь нумерует его —
   так у имени по умолчанию остаётся один источник (веб, где оно и показывается
   подсказкой), а старые клиенты без признака получают прежнее поведение.
   - HTTP: `POST /api/sessions` тело `{name, root, dir, preset, autoName?}` →
     `200 {ok: true, session: "<фактическое имя>"}`.
   - Relay: кадр `Create{name, root, dir, preset, autoName?}` →
     `CreateOk{session: "<фактическое имя>"}` (поле уже есть — сейчас в нём эхо
     запрошенного имени; станет фактическое).
   - `SessionService.create(req)` возвращает `{ name }` вместо `void`.

3. **Подбор имени — чистая функция `pickFreeName(base, taken)`.** Если `base` не
   занято — `base`. Иначе для n = 1, 2, …: кандидат = `base`, обрезанная до
   `40 − len(n)` символов, + `n`; первый не занятый — ответ. Верхняя граница перебора —
   константа (10 000), после неё ошибка; практически недостижима. Никаких разделителей,
   никакого разбора цифр на конце базы (см. историю 8).

4. **Занятые имена — сырой `tmux list-sessions -F '#{session_name}'`.** Не `list()`:
   тот прячет сборочные сессии Gradle и делает лишний `list-panes`. «No server running»
   трактуется как пустой список (как в `list()`), любая другая ошибка пробрасывается.

5. **Гонка — по ответу tmux.** Если `new-session` падает с exit 1 и `duplicate session`
   в stderr (и только тогда), кандидат добавляется в занятые и подбирается следующий;
   не больше 5 попыток. Без `autoName` ошибка tmux пробрасывается как сегодня.

6. **Валидация не ослабляется.** `name` по-прежнему обязан проходить `NAME_RE`
   (`^[\w-]{1,40}$`) до всякого подбора; кандидаты по построению остаются в этом
   алфавите и длине. Имена тасок/аргументы здесь не при чём — командная строка tmux
   константна, имя едет отдельным аргументом `execFile`, как и раньше.

7. **Веб: `Transport.create` возвращает фактическое имя (`Promise<string>`).** LAN — из
   `session` ответа, relay — из `CreateOk.session`; если поле отсутствует (старый
   агент) — запрошенное имя. Модалка передаёт `autoName: поле «Имя» пустое` в обеих
   формах и вызывает `onCreated(<фактическое имя>)` — все пять мест вызова уже
   принимают имя и уходят на `#/term/<имя>`, менять их не нужно.

8. **Новых строк UI нет** — ни тостов, ни ключей i18n: результат виден в шапке
   открывшейся сессии. Сообщения об ошибках не меняются.

9. **Документация:** в README (en + ru) — правило именования для кнопки «+» и для `tm`
   («имя по умолчанию — имя папки; если занято — `MyProject1`, `MyProject2`…»),
   там же исправить устаревшее «`tm` создаст сессию `main`». Обе версии синхронно.

10. **`tm` — та же нумерация в шелле.** Функция `tm` печётся `setup` в rc-файл
    (`TM_FUNCTION` в `setup.ts`); правило повторяется на POSIX sh, потому что агент
    в этот момент может быть не запущен, а `tmux` под рукой всегда:
    - без аргумента: база = `basename "$PWD"` (как сейчас, без санитизации);
      кандидат «занят», если он дословно есть в выводе
      `tmux -L termhub list-sessions -F '#{session_name}'` (точное сравнение целой строки,
      вроде `grep -qxF`); пока занят — следующий кандидат `<база><n>`, n = 1, 2, …;
      затем `tmux -L termhub new -s <кандидат>` (без `-A` — цель именно новая сессия);
      нет сервера → список пуст → имя свободно;
    - с аргументом: `tmux -L termhub new -As "$1"` — без изменений;
    - **D01 (таск 04):** проба через `has-session -t "=<кандидат>"`, как было решено
      сначала, не годится — для tmux `=foo.bar` это «сессия foo, панель bar», и папка с
      точкой в имени (`v1.1`, `my.app`) всегда считалась свободной, а `new -s` затем падал
      с «duplicate session». Сравнение по списку имён нечувствительно к разделителям
      target и по-прежнему точное (`MyProject` не совпадает с `MyProject1`);
    - гонку двух одновременных `tm` из разных терминалов сознательно не закрываем:
      tmux ответит «duplicate session», повторный `tm` возьмёт следующий номер.
    Следствие, о котором сказать пользователю: `tm` без аргумента больше не
    присоединяется к существующей сессии папки — для этого `tml` или `tm <имя>`.

11. **Обновление уже прописанного блока.** `setup` при наличии маркера `# termhub`
    проверяет, есть ли в файле текущее определение `tm`. Если нет — ищет прежнюю
    однострочную `tm() { tmux … }` и предлагает заменить ровно эту строку новой функцией
    (`Update tm? [Y/n]`), ничего больше в файле не меняя; если строка не распознана —
    печатает новое определение и просит вставить вручную. Чистый помощник
    `upgradeTmFunction(existing) -> string | null` делает замену в тексте — его и тестируем.

12. **Сокет `tm` параметризуется для тестов.** `tmFunction(socket = TMUX_SOCKET)` строит
    текст функции; `TM_FUNCTION` = `tmFunction()`. Логика шелла проверяется
    детерминированно — подложным `tmux` в `PATH` (скрипт, который помнит «занятые» имена
    и логирует аргументы `new`), а не живым attach, которому нужен tty.

13. **Модалка закрывается «в сторону» маршрута, а не назад.** Причина бага R11:
    `openModal.close()` снимает свою history-запись через `history.back()` — это
    асинхронная траверса, а `onCreated` тут же ставит `location.hash` синхронно. Браузер
    сперва пушит `#/term/new`, потом исполняет отложенный `back` уже от новой записи и
    возвращается на запись модалки с URL старой сессии; роутер сносит только что
    смонтированное пространство новой сессии. Исправление: `close` получает необязательный
    аргумент `next` (hash); с ним модалка делает `cleanup()` и `location.replace(next)` —
    свою запись **заменяет** маршрутом, никакого `back()`. История получается
    `[откуда пришёл, новая сессия]` — «Назад» ведёт ровно на шаг. `openCreateModal`
    навигирует сам: `close(termHash(created))`; параметр `onCreated` у всех пяти вызовов
    исчезает (все они делали одно и то же). `termHash(name)` — в `routes.ts`, единый
    источник формата `#/term/<имя>` вместо пяти копий. `close()` без аргумента — как
    прежде (`history.back()`), «Назад» на открытой модалке — как прежде (`popstate → cleanup`).

14. **Фокус переносится при переключении, а не при подключении.** Причина бага R13:
    единственный `term.focus()` живёт в `onStatus('connected')` — асинхронно, через
    сеть, и только при включённом ⌨; кнопки табов не гасят `mousedown`, так что тап
    сперва уводит фокус с textarea xterm (на телефоне — закрывает клавиатуру), а снос
    старого терминала оставляет фокус на `<body>`. Исправление в трёх точках:
    - `tabs.ts`: `mousedown` по кнопке таба → `preventDefault()` (как в `quickkeys.ts`);
    - `term.ts`: сразу после `term.open(host)` и `applyKeyboardMode()` — `term.focus()` безусловно;
      фокус на `connected` (при включённом ⌨) остаётся как есть;
    - `workspace.ts`: `show('term')` вызывает `focus()` хэндла терминала — безусловно.
    Бриф требует фокус без оговорок, и тумблер ⌨ здесь не условие для фокуса, а режим
    поля ввода: при выключенном тумблере textarea xterm стоит в `inputmode=none`, поэтому
    фокус даёт работу аппаратной клавиатуре и не поднимает экранную. Принудительный
    фокус когда-то убирали, потому что он открывал клавиатуру на каждую стрелку, — тогда
    режим поля не выставлялся; сейчас `applyKeyboardMode` обязан отработать до фокуса.
    Остаточный риск (старые iOS без поддержки `inputmode=none`) — в приёмке вживую.

15. **Ввод до подключения не теряется.** `LanTransport.write` молча роняет байты, пока
    WebSocket не `OPEN`; через relay окно до `OpenOk` ещё шире. Экран терминала копит
    `sendData` в очередь, пока статус ≠ `connected`, и сбрасывает её сразу **после**
    `sendResize()` (инвариант «первый кадр — RESIZE» неприкосновенен). Очередь
    ограничена 8 КБ (лишнее отбрасывается с конца), при `onEnd` очищается.

16. **Enter гасится, keypress подавляется.** Причина бага R14/R15: ветка «перенос» в
    `attachCustomKeyEventHandler` шлёт `\x1b\r` и возвращает `false`, но не вызывает
    `preventDefault()`; xterm при `false` выходит до своего `cancel()`, браузер порождает
    `keypress`, `_keyPress` xterm шлёт `\r` через `onData` — одно нажатие = перенос +
    отправка. Так было с первого коммита; правка 2026-07-30 лишь расширила путь
    «перенос» на выключенный тумблер, отчего баг стал «независимо от переключателя».
    Исправление: решение по Enter — чистая функция `enterAction({type, key, shiftKey},
    enterSends) -> 'send' | 'newline' | 'suppress' | 'pass'` в своём модуле:
    - `keydown` Enter: `shiftKey || !enterSends` → `newline` (шлём `\x1b\r`,
      `preventDefault()`, `return false`); иначе `send` (`return true` — xterm сам шлёт
      `\r` и гасит событие);
    - `keypress` Enter → `suppress` (`preventDefault()`, `return false`) — страховка от
      второго `\r` и от `\n` в скрытой textarea;
    - `keyup` и всё остальное → `pass` (`return true`; xterm на `keyup` держит перефокус).
    Быстрая клавиша Enter на панели (`quickkeys.ts`) шлёт `\r` напрямую — без изменений.

17. **Живая проверка.** Поведение history и клавиатуры в happy-dom не воспроизводится
    (`History.back()` там синхронный). Кроме тестов, приёмка делает контрольный прогон в
    настоящем Chrome: создание сессии из полосы вкладок, Enter/Shift+Enter в обоих
    положениях тумблера с проверкой байтов, уходящих в pty.
