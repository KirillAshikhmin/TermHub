# Границы и правила прогона

Этот файл читает каждый исполнитель перед тем, как что-либо написать.

## Что поставляет этот прогон

Экран ленты в приложении — третий и последний этап пути. Работа в `packages/web/`.

**Одно исключение (D01, решение координатора 14.09.2026):** таску 01 разрешено править
`packages/agent/src/relay-link.ts` и его тест — отказ ленты обязан ехать кадром
`FeedResult{ok:false, reason:'forbidden'}`, а не общим кадром ошибки, иначе гость получает в
ленту чужой отказ контрольного канала. Всё остальное на стороне агента по-прежнему не трогаем.

## Правила проекта, которые нельзя вывести из кода

- **UI-строки — только через `i18n.ts`**, оба словаря (ru+en) с одинаковым набором ключей;
  это проверяется тестом. Ни одной строки в разметке.
- Веб не типизируется сборкой: после правок `packages/web/src/` обязателен
  `npx tsc -p packages/web/tsconfig.json --noEmit`.
- Стили — в `packages/web/src/theme.css`, классы с префиксом `th-`, как у соседей.
- Никаких `@author`, копирайтов и подписей инструментов.
- Не хватает зависимости — возвращай `BLOCKED`, а не ставь её.
- Строки в markdown — до ~95 знаков.

## Границы, решённые в спецификации

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `feed-client` (веб) | запросом ленты у агента по обоим транспортам | `Transport.feed(session, opts)`, типы `FeedEntry`/`FeedResult` в вебе | различие LAN и relay |
| `feed-view` (веб) | экраном: отрисовка, листание, приращение, тумблер мышления | `mountFeed(host, session, transport) -> {el, teardown}` | вид записи, склейку страниц, опрос |
| `feed-search` (веб) | поиском по ленте и переходом к месту | `searchFeed(state, query) -> Hit[]`, `jumpTo(hit)` | дочитывание назад, подсветку |

**Швы для тестов — два, оба уже есть в проекте:** мок транспорта (образцы —
`packages/web/test/term-mode.test.ts`, `dashboard-relay.test.ts`) и `happy-dom` для разметки.
Новых швов не заводить.

## Что уже готово на стороне агента — опираться, не перепроверять

- LAN: `GET /api/feed?session=<имя>&limit=&before=&after=&around=` → JSON; отказ едет полем
  `ok:false`, а не кодом HTTP. Пустое значение параметра равно отсутствующему.
- Relay: кадр `FrameType.Feed = 46` с payload `{session, limit?, before?, after?, around?}`,
  ответ `FrameType.FeedResult = 47` — то же тело на канале запроса. Корреляции по
  идентификатору нет: один запрос за раз, как с кадром возможностей.
- Ответ: `{ok:true, agent:'claude'|'codex', entries, head, tail, bof, eof, complete, live,
  skipped}` либо `{ok:false, reason, detail}` с пятью причинами (`no-agent`,
  `unknown-format`, `no-transcript`, `lookup-failed`, `cursor-stale`).
- Запись:

```ts
interface FeedEntry {
  id: string;
  at: number;                       // epoch ms
  kind: 'human' | 'agent' | 'thinking' | 'tool' | 'note';
  text: string;
  tool?: string;                    // только у kind:'tool'
  note?: 'compacted' | 'interrupted' | 'error' | 'chain';
  branch?: string;                  // на сегодняшних данных пусто ВСЕГДА — веток не рисовать
  truncated?: true;                 // текст обрезан по 64 КиБ
  cursor?: string;                  // «<inode>:<offset>» этой записи — точка прыжка
}
```

- `limit` по умолчанию 200, максимум 1000; ответ не больше 1 МиБ, поэтому **страница бывает
  короче запрошенного лимита, не достигнув края**.
- **Конец ленты — `bof`/`eof`, а НЕ пустой список записей.** Пустая страница со сдвинутым
  курсором означает шаг через строку, не влезшую в окно; остановившись на ней, потеряешь
  всё, что за ней.
- Возможность называется `feed`; пересечение уже считает `packages/web/src/capabilities.ts`
  (`hasCap('feed')`, `negotiatedCaps()`).
- Мышление у Codex всегда пустое (0 непустых из 53 265) — поэтому по умолчанию скрыто.
- Проверено на живых данных: 11 из 12 сессий владельца отдают ленту, двенадцатая —
  `no-transcript`.

## Как устроен веб, чтобы не изобретать заново

- `packages/web/src/workspace.ts` — вкладки сессии (`term | files | repo | gradle`),
  ленивое монтирование, переключение показом: терминал под другой вкладкой не рвётся.
  Лента становится пятой вкладкой там же.
- `packages/web/src/routes.ts` и разбор в `main.ts`/`remote.ts` — маршруты вида
  `#/sfiles/<сессия>`; лента получает `#/sfeed/<сессия>`.
- `packages/web/src/transport.ts` — интерфейс транспорта; LAN-реализация в `api.ts`,
  relay — в `relay-transport.ts`. Образец пары «запрос-ответ» без корреляции — `capabilities`.
- `packages/web/src/i18n.ts` — словари; `theme.css` — стили.
- `packages/web/src/touch-scroll.ts` — тач-жесты терминала; ленте нужна обычная прокрутка,
  этот модуль ей не нужен.

## Что построили завершённые таски

### Из таска 03 — поиск и переход к месту

- Поиск живёт в `searchSlot` экрана и состояния не держит: находки считаются над `entries()`,
  переход идёт через `jumpTo(cursor)`, подсветка принадлежит экрану.
- Дочитывание назад — строгой очередью заходов, с паузой набора 300 мс: иначе заходы
  сталкивались и врали счётом просмотренных записей (найдено живьём).
- Ловушка вёрстки: `display` у `.th-btn` перебивает атрибут `hidden` — нужен явный
  `[hidden] { display: none }`, иначе кнопка «искать дальше» висит всегда (найдено живьём).
- Поиск идёт по тексту записи; имя инструмента в строке `tool` не ищется — в спеке этого нет.
- Проверено живьём на беседе Codex: «checkpoint» → «Найдено: 2» без запроса к агенту, прыжок
  подсветил запись; слово, которого в беседе нет, дало 20 страниц дочитывания и строку
  «Просмотрено записей: 1969, дальше не искали» с кнопкой.

### Из таска 02 — экран ленты

- `mountFeed(host, session, transport) -> FeedHandle` в `packages/web/src/feed.ts`:
  `{el, searchSlot: HTMLElement, entries(): FeedEntry[], loadOlder(): Promise<boolean>,
  jumpTo(cursor: string): Promise<void>, teardown()}`.
- **Для таска 03:** `searchSlot` — пустой узел над списком, туда монтируется поиск;
  `entries()` — снимок загруженного; `jumpTo(cursor)` тянет `around` и подсвечивает запись
  классом `.is-hit` на 2 секунды. Владелец состояния и подсветки — экран, поиск состояния не
  держит.
- `loadOlder(): Promise<boolean | null>` — `true` = страница дочитана и начало ещё впереди,
  `false` = начало беседы достигнуто, `null` = экрана больше нет и ответа о беседе не
  существует. «Занято» ответом не бывает: вторая просьба ждёт ту же подкачку и получает её
  итог, поэтому своей очереди вызывающему не нужно.
- `[hidden]` — одно правило на всё приложение в начале `theme.css`; поштучных заплаток
  («у .th-btn свой display») больше нет и заводить их не надо.
- `whenCap(name, transport): Promise<boolean>` в `capabilities.ts` — единственный ответ веба на
  вопрос «умеет ли этот агент»; вторых копий не заводить.
- Подсветка отмечает всю строку курсора и ведёт к **видимой** записи: агент даёт всем записям
  одной строки транскрипта один курсор, и первый элемент с этим курсором бывает скрытым
  мышлением (проверено живьём: на 200 записях есть группа `["agent","tool"]`).
- Маршрут — `sfeedHash(session)` в `routes.ts`; строки — секция `feed.*` в `i18n.ts`.
- Запросы ленты выстроены очередью внутри экрана: листание вверх поверх идущего приращения
  давало гонку, она закрыта и закреплена регресс-тестом.
- Проверено живьём на LAN: вкладка пятая, лента открывается на хвосте, колесо вверх тянет
  предыдущие и держит позицию под пальцем, в фоне (`visibilityState=hidden`) опрос не идёт,
  на ширине 320 px ни одна запись не шире своего блока.
- Известное и не наше: holo-бар вкладок на 320 px обрезает подписи — так было и при трёх
  вкладках, пятая лишь ужимает сильнее.

### Из таска 01 — клиент ленты

- `Transport.feed(session: string, opts?: FeedOptions): Promise<FeedResult>` — один вызов на оба
  транспорта; LAN в `api.ts`, relay в `relay-transport.ts`.
- Типы объявлены в `api.ts` и реэкспортированы из `transport.ts` — **импортировать из
  `'../src/transport'`**, из пакета агента ничего не тянуть.
  `FeedOptions {limit?, before?, after?, around?}`; `FeedResult = FeedPage | FeedFailure`;
  `FeedPage {ok:true, agent, entries, head, tail, bof, eof, complete, live, skipped}`;
  `FeedFailure {ok:false, reason, detail}`.
- `FeedFailureReason` — пять причин ленты **плюс `forbidden`**: гостевой отказ relay приезжает
  значением, а не исключением, иначе экрану пришлось бы знать транспорт.
- Запросы ленты через relay сериализованы очередью, один в полёте; ответ на сдавшийся по
  таймауту запрос съедается счётчиком, чтобы не достаться следующему.
- Оговорка: кадр `Error` идёт без идентификатора, поэтому адресуется единственному запросу
  ленты в полёте; при совпадении по времени чужой гостевой отказ контрольного канала может
  достаться ленте.
- Тестовая обвязка relay вынесена в `packages/web/test/relay-harness.ts` — переиспользовать.
- Замер базы: `npx vitest run packages/web/test/` было 329, стало 337.
