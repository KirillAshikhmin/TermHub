# Спецификация: открытие файла на хосте

## Задача

Пользователь просматривает файл в Проводнике TermHub с телефона или другого
браузера и хочет одним нажатием открыть этот же файл нативным приложением на машине,
где работает агент TermHub — прежде всего на Mac.

## Решение

В подвале просмотра файла рядом с «Открыть в NotAText» появляется кнопка
«Открыть на хосте». Она отправляет существующую файловую операцию агенту. Агент
повторно разрешает реальный путь внутри настроенных корней и запускает системный
opener без shell. Успех и ошибка видны через toast; Проводник остаётся открытым.

## Решения по реализации

1. Использовать существующий `FileOp`/`FileOpResult`, добавив action `open-host`.
   Так LAN и relay получают один контракт без нового типа протокольного кадра.
2. Безопасное разрешение пути остаётся внутри `FileService`; наружу не возвращается
   абсолютный путь. Перед opener проверяется обычный файл.
3. OS-команда выбирается в маленьком test seam: `darwin → open`, `linux → xdg-open`.
   Запуск — argv без shell; ненулевой exit и spawn error превращаются в reject.
4. Host-open — локальный side effect, поэтому relay-гостю нужен `write`; владельцу LAN
   действие доступно после обычной авторизации.
5. UI использует один builder host-кнопки во всех ветках preview, чтобы тип файла не
   менял доступность и обработку ошибки.
6. В ответе нет локального пути: только успешный пустой result или текст ошибки.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `host-opener` | выбор OS-команды и жизненный цикл процесса | `openPathOnHost(path) -> Promise<void>` | `spawn`, платформенные имена команд и exit-коды |
| `file-service` | roots/realpath/type safety | `openOnHost(root, subpath) -> Promise<void>` через `runFileOp` action `open-host` | абсолютный путь хоста |
| `transport` | LAN/relay доставка action | существующий `fileOp('open-host', {root, path})` | REST/FrameType детали |
| `file-viewer` | видимость, pending и feedback кнопки | кнопка `files.openHost` в footer | тип preview и transport mode |

Швы тестирования: чистый/инъецируемый `host-opener`, `runFileOp`, relay permission,
LAN route и DOM-harness модалки файла. Новых frame types и полей протокола нет.

## Вне рамок

- Открытие папки в Finder/Проводнике ОС — пользователь просил файл из file viewer.
- Выбор конкретного desktop-приложения — используется системное приложение по умолчанию.
- Отмена уже переданного системному opener действия.
- Windows-host: TermHub сейчас поддерживает macOS/Linux; возвращается явная ошибка.

## Поправка: реальное копирование из Codex

Codex включает mouse tracking в terminal TUI. Поэтому обычный drag попадает в
приложение, а xterm не создаёт selection; прежний snapshot-контроллер получает пустую
строку и ему нечего копировать. На macOS TermHub должен разрешить штатный принудительный
selection xterm через Option+drag, после чего уже реализованные auto-copy и Command+C
работают с этим selection. Обычный клик без Option остаётся доступен Codex.

Приёмка: настройка передана настоящему `Terminal`, тест моделирует активный mouse mode,
а EN/RU manual checklist явно называет Option+drag для Codex на Mac.
