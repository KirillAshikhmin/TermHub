# Границы и правила прогона

Этот файл читает каждый исполнитель перед тем, как что-либо написать.

## Что поставляет этот прогон

**Документы, а не код.** Решение пользователя (вопрос 1 брифинга): анализ, решения и
дорожная карта. Код по этапам дорожной карты пишется следующими прогонами.

Значит: никаких правок в `packages/*`, никаких новых зависимостей, никаких изменений
поведения приложения. Только `docs/`.

## Правила проекта, которые нельзя вывести из кода

- Язык документации в `docs/` — **русский**. `README.md` и `CONTRIBUTING.md` двуязычные
  (`*.md` английский + `*.ru.md` русский), но этот прогон их не трогает: функциональность
  не менялась.
- Формат ADR в проекте задан существующими файлами `docs/adr/0001`…`0012`. Разделы:
  `## Контекст`, `## Решение`, `## Почему`, `## Последствия`. Заголовок — `# NNNN. <решение
  одной строкой>`. Отклонённые варианты перечисляются в «Почему» явными фразами
  «Отвергнут вариант …».
- Нумерация ADR сквозная, последний занятый номер — `0012`.
- Никаких `@author`, копирайтов и подписей инструментов в файлах проекта.
- Строки в markdown — до ~95 символов, как в существующих ADR.
- Проверки прогона: `npx vitest run` и `npm run build` должны остаться зелёными. Этот
  прогон код не трогает, поэтому достаточно убедиться, что ничего не сломано.
- Не хватает данных для решения — возвращай `BLOCKED` с вопросом, не выдумывай факты.

## Измерено на живом tmux 3.7b 12.09.2026 — опираться на это, не перепроверять

Проба гоняла tmux на изолированном сокете через `node-pty` (та же среда, что у агента).

| Что | Результат |
|---|---|
| Первые байты `tmux attach` | `ESC[?1049h` — alt-screen сразу и до detach |
| Первые байты `tmux -CC attach` | alt-screen не приходит вообще |
| Протокол control mode | строчный: `%begin/%end`, `%session-changed`, `%output %<pane> <октальное экранирование>`, `%layout-change` |
| Статусная строка tmux в control mode | клиенту не приходит |
| Стоимость подключения в control mode | десятки байт (83 в этой пробе, 78 в независимой — разница на длине имени сессии), перерисовки экрана нет |
| Ввод байтов из control mode | `send-keys -t <сессия> -H <hex>` — работает |
| Размер окна из control mode | `refresh-client -C 100x30` — работает, держится после ухода клиента |
| История панели | `capture-pane -p -e -S -` отдаёт всё до `history-limit`; проба шла на 4000 строках. Сам лимит задаёт проект: `set -g history-limit 50000` в `packages/agent/src/setup.ts` |
| Цена истории | 89 байт на строку; 3000 строк = 266 КБ, 57 мс на стороне tmux |
| Второй alt-screen — от приложения внутри панели | `vim` → `alternate_on=1`; **Claude Code 2.1.269 → `alternate_on=0`**, **Codex 0.153.4 → `alternate_on=0`** (замер 12.09.2026, тот же изолированный сокет) |
| Гарантия для Codex | флаг `--no-alt-screen` есть в `codex --help`: «Runs the TUI in inline mode, preserving terminal scrollback history» |
| Версии на машине | tmux 3.7b, Claude Code 2.1.269, Codex CLI 0.153.4, xterm.js 6.0.0, Node 22 |
| mosh | на машине не установлен; вердикт вынесен по свойствам протокола, не по замеру |

## Границы, решённые в спецификации

Скопировано из `spec.md`, раздел «Границы и швы». Это контракт будущих этапов — ADR и
дорожная карта описывают именно эти единицы, не изобретая своих.

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `control-protocol` | разбором строк control mode | `parse(chunk) -> Event[]` (`output` / `layout` / `reply` / `error`), `escapeInput(bytes) -> string` | октальное экранирование, склейку чанков, состояние `%begin/%end` |
| `session-link` (агент) | жизненным циклом control-клиента, нумерацией вывода, кольцевым буфером | `open(session, opts) -> Link`, `Link.resumeFrom(seq)`, `Link.write(bytes)`, `Link.resize(cols, rows)`, `Link.snapshot(lines)` | выбор control mode или attach, откат, спавн pty |
| `term-history` (веб) | локальной историей сессии и её персистом | `append(session, bytes)`, `read(session) -> bytes`, `clear(session)`, `size(session) -> bytes` | хранилище, лимит, вытеснение, деградацию без хранилища |
| `echo` (веб) | предиктивным локальным эхо | `predict(bytes)`, `confirm(seq)`, `reset()`, `enabled(rtt) -> boolean` | порог задержки, разметку неподтверждённого |
| `agent-ui` (веб) | распознаванием рамки ввода, вопроса и границ блоков | `frame(screen) -> Region \| null`, `question(screen) -> Choice[] \| null`, `blocks(buffer) -> Bound[]` | эвристики под конкретных агентов |
| `agent-profiles` | знанием о конкретных агентах как данными | `profiles: Profile[]`, `match(session) -> Profile \| null` | состав профиля, порядок сопоставления |
| `prompt-editor` (веб) | строкой ввода, черновиком, диктовкой, вложениями | `mount(host, handlers) -> Editor`, `Editor.draft()`, `Editor.send()` | хранение черновика, работу с файлами |

**Швы для тестов — два:** `control-protocol.parse` (чистая функция над байтами) и
`agent-ui` (чистые функции над снимком экрана). Всё остальное проверяется через
существующие швы проекта: моки транспорта в вебе, изолированный tmux-сокет в тестах агента.

## Что уже существует в продукте и не должно потеряться

- Заголовки сессий Claude и Codex (`packages/protocol/src/session-title.ts`), пресеты
  запуска, индикатор активности и звонок.
- Копирование при mouse tracking Codex (Option+drag, повторное `Command+C`).
- Кликабельные пути и ссылки OSC 8 с белым списком схем.
- Compose bar, панель быстрых клавиш, тумблеры клавиатуры и «отправлять по Enter».
- Тач-скролл с инерцией и режим тач-выделения.
- Read-only гость через relay: ввод запрещён и на клиенте, и на агенте.
- Обещание «на Mac не открывается ни один входящий порт».

## Что решено и не подлежит пересмотру в этом прогоне

Решения приняты пользователем на брифинге. ADR фиксируют их, а не переоткрывают.

1. Ядро xterm.js остаётся; «своим» становится обвязка (вопрос 2).
2. mosh как замена tmux отвергнут; берутся три идеи его протокола (вопрос 3).
3. История живёт в памяти и в хранилище устройства, без шифрования, с лимитом (вопрос 4).
4. Рамка ввода агента скрывается, когда открыта своя строка ввода (вопрос 7).
5. Размер окна tmux телефон продолжает задавать всем клиентам — «оставить как есть» (вопрос 8).
6. Текст вопроса агента кладётся в push-уведомление (вопрос 12).

## Из таска 01 — шесть ADR

- `docs/adr/0013` — ядро xterm.js остаётся парсером и рендером, своим становится обвязка.
- `docs/adr/0014` — подключение через `tmux -CC attach`, ввод `send-keys -H`, размер
  `refresh-client -C`, срез `capture-pane -p -e -S -N`, откат на `tmux attach` одним
  решением при подключении с записью причины.
- `docs/adr/0015` — mosh как транспорт отвергнут; взяты три идеи его протокола.
- `docs/adr/0016` — история в обычном буфере xterm плюс хранилище браузера, лимит 10 000
  строк на сессию, без шифрования, гость не пишет, выход и отзыв чистят.
- `docs/adr/0017` — рамка агента скрывается по тумблеру ✎, поиск снизу вверх по трём
  признакам, шесть случаев «не скрываем»; знание об агентах — профили-данные (§10a спеки).
- `docs/adr/0018` — клиент объявляет возможности, агент отвечает своими, работа по пересечению.
- Метки требований в текст ADR не выносятся: в ADR прошлых прогонов те же коды означают
  другое.
- Порог включения предиктивного эха — 50 мс как стартовое значение до замера на живом LTE.
  Ссылаться на mosh как на источник числа нельзя: он на машине не установлен.
- `capture-pane` остаётся двумя путями сразу: первый экран при отсутствии локальной истории
  **и** восстановление, когда кольцевой буфер не покрыл разрыв. Формулировки `0014` и `0016`
  должны читаться одинаково.
