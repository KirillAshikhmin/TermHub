## Что должно заработать

Появляется разбор осуществимости с замерами на живых Claude Code и Codex и фундамент чата:
формы провода в пакете протокола, профили двух агентов как данные и чистая функция, которая
по строкам экрана панели говорит, что на нём: агент ждёт ввода, работает, задаёт вопрос с
вариантами, просит разрешение, показывает известное меню — или экран не узнан.

Замеры делаются на живых агентах, запущенных **только на отдельном сокете tmux**
(`-L termhub-probe-<uniq>`, в конце `kill-server`) во временном каталоге с нейтральными
запросами. Рабочий сокет `termhub` и сессии владельца не трогать и их экраны в репозиторий не
класть: репозиторий публичный. Из снимков убрать домашний путь, имя пользователя и почту.
Транскрипты владельца читать можно только для выяснения формы записей; их содержимое в
репозиторий и в документ не попадает.

Если замер показал, что какая-то часть задачи не работает вовсе (экран не читается, клавиши
не доходят, вопрос нельзя отличить от текста) — не обходить: вернуть это в отчёте списком
«не работает» со статусом DONE_WITH_CONCERNS.

## Из брифа, дословно

> «проанализируй, на сколько возможно реализовать такую фичу: на бекенде claude и codex работают в терминале, а мы с нии через наш веб через нативный интерфейс, то есть по сути парсить терминал. Что бы работать удобнее было, но использовать именно родной инструмент и не переписывать его. осознаю что с обновлением это может сломаться, поэтому будет переключение между терминалом и нативным интерфейсом.»

## Критерии приёмки

- [ ] `docs/native-agent-ui.ru.md` существует: по каждой части (переписка, ввод с переносами, вопросы, разрешения, подсказки по «/», режим, модель, контекст, очередь, вложение не-картинки) — вердикт, чем измерено, версии Claude и Codex, версия tmux
- [ ] Документ отвечает на каждый пункт «Не удалось выяснить» из `notes.md` или говорит, почему ответа нет
- [ ] В документе измерено: видимый экран Claude в альтернативном буфере читается `capture-pane`; текст с переносами доходит одним запросом через bracketed paste; какие клавиши отвечают на вариант вопроса у каждого агента; чем переключается режим и чем меняется модель; есть ли на экране очередь; что агент делает с вставленным путём не-картинки
- [ ] Снимки экранов лежат фикстурами: для каждого из двух агентов — ожидание ввода, работа, вопрос с вариантами, запрос разрешения, меню, текст в строке ввода, список по «/»; у каждого — версия агента и размер панели; личных данных в них нет
- [ ] `@termhub/protocol/chat` экспортирует типы из `interfaces.md` и `questionStamp`; пакет собирается, libsodium в этот подпуть не тянется
- [ ] `FrameType` получил номера 48–53, `CAP_CHAT` стоит в `AGENT_CAPS` и `CLIENT_CAPS`; существующие тесты возможностей зелёные
- [ ] `profileOf('claude')` и `profileOf('codex')` отдают клавиши, режимы, модели, встроенные команды и диапазон проверенных версий, взятые из замеров; `isTested` отвечает ложью для версии новее проверенной
- [ ] `readScreen` на каждом снимке отдаёт ожидаемый `kind`; для вопроса и разрешения — заголовок, все варианты и `stamp`; для ожидания ввода — режим и текст строки
- [ ] `readScreen` на экране обычной оболочки, на пустом экране и на обрезанном пополам снимке отдаёт `unknown`, а не вопрос
- [ ] Вопрос, переснятый при другой ширине панели (строки перенесены), даёт тот же `stamp`
- [ ] `readPopup` на снимке списка по «/» отдаёт команды с подсказками
- [ ] Отчёт называет фактические находки, расходящиеся с `interfaces.md` (формы, которых нет, лишние поля), — списком для правки границ
