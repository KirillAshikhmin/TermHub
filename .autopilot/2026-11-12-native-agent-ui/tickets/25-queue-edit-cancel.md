# 25 — Правка и отмена сообщения в очереди агента

**Требования:** G40, G42, G46, G47, G48, G49, G50, G51
**Зависит от:** 23, 24
**Зона:** `packages/protocol/` · `packages/agent/` · `packages/web/` · `docs/native-agent-ui.ru.md`
**Волна:** 18
**Ревью:** да — клавиши очереди
**Модель:** сильная

## Что должно заработать

Сообщение, отправленное работающему агенту, встаёт в его очередь. Сейчас чат его только
показывает. Нужно уметь отменить его и поправить — теми средствами, которые даёт сам агент.
В этот же таск входит починка того, что не сработало в живой проверке отправки на настоящих
агентах (её отчёт — `live-check.md` в папке сборки).

## Из брифа, дословно

> «Правка и отмена сообщений в очереди - давай сделаем.»

> «Отправка: проверь»

## Разделы спецификации

Истории 21б, 27, 27а, 27б, 27в.

## Критерии приёмки

- [ ] Измерено на настоящих Claude Code и Codex (отдельный сокет tmux, одна сессия на агента, сервер гасится сразу после замера) и записано в `docs/native-agent-ui.ru.md`: как каждый агент показывает очередь; чем сообщение очереди возвращается в строку ввода на правку (у Codex подвал называет «⇧← edit last queued message»); чем убирается из очереди; можно ли выбрать не последнее сообщение; что из этого агент не умеет
- [ ] Обезличенные снимки этих экранов лежат фикстурами; экран очереди читается с текстами сообщений очереди, когда агент их рисует
- [ ] Действие чата «вернуть из очереди» шлёт измеренную клавишу только при свежем экране с очередью, после неё проверяет, что текст оказался в строке ввода, забирает его (как `take-input`) и оставляет строку агента пустой; не сошлось — отказ, клавиш больше нет
- [ ] «Отменить» в чате — возврат из очереди без подстановки текста в поле; «Изменить» — с подстановкой в поле ввода чата
- [ ] Кнопки есть только у тех сообщений очереди, до которых агент позволяет добраться (если только последнее — только у последнего); у агента, который правку очереди не даёт, кнопок нет, и это названо
- [ ] Гость без `write` кнопок не видит; действие от гостя — `forbidden`
- [ ] Каждый пункт «не сработало» из `live-check.md` починен с тестом на снимке либо назван в отчёте с причиной
- [ ] Прежние снимки дают прежние вердикты; строки в обоих словарях; `tsc` агента и веба чист
- [ ] Веб запускает сверку списка команд новой формой: по первому «/» в поле ввода — `POST /api/commands {session, verify: true}` на LAN и кадр `Commands {id, session, verify: true}` через relay; обычное чтение списка остаётся прежним запросом без клавиш
- [ ] Сессия Codex до первого сообщения в беседе (на экране обычная пустая строка ввода, транскрипта ещё нет) отвечает состоянием и принимает первый запрос, а не `no-agent`
- [ ] Тесты, поднимающие свой сокет tmux, после `kill-server` убирают и файл сокета: прогон тестов не оставляет файлов `termhub-test-*` и `termhub-feed-*` в каталоге сокетов tmux
- [ ] Открытый вопрос очереди Codex с подвалом «enter submit   ^] skip   ⇧→ main prompt   ⇧← queued messages» (в очереди есть ещё сообщения) читается как вопрос с вариантами и «Other»; ответ кнопкой и своим текстом идёт прежним измеренным путём; дополнительные пункты подвала после «enter submit» и «skip» вопрос неузнанным не делают; экран без «enter submit» или без вариантов остаётся неузнанным
- [ ] Ждущий Codex с пользовательской строкой состояния и текстом в строке ввода: под строкой состояния нет строки подсказок либо стоит только правое уведомление («⚠ N warnings · f2 to view») — экран читается как `idle` с `input`, `prompt` вставляет текст, подтверждает его и отправляет; правое уведомление рядом с подсказками («← for agents · ? for shortcuts … ⚠ 3 warnings · f2 to view») узнанный экран неузнанным не делает; измерено на настоящем Codex, какие виды принимает последняя строка подвала у ждущего и работающего агента с пустой и непустой строкой ввода
- [ ] Узнавание «агент у строки ввода» у Codex и у Claude держится на строке ввода (знак, место, оформление) и на том, что в панели идёт процесс агента; строки подвала ниже неё — источник сведений, а не условие: незнакомая строка или пункт подвала, пустая строка, правое уведомление экран неузнанным не делают; из подвала по-прежнему читаются режим, состояние, модель, подсказка очереди, число фоновых агентов — когда они там есть
- [ ] Диалоги узнаются по строению (строка вопроса или заголовок, варианты с номерами, указатель), подвал диалога определяет только его вид; незнакомый пункт в подвале диалога его неузнанным не делает; экран без вариантов или без указателя вопросом не считается
- [ ] Все прежние снимки дают прежние вердикты; оболочка, пустой экран и обрезанный снимок (без строки ввода) остаются неузнанными; для каждого из пяти живых отказов этой сборки (список фоновых агентов Claude, подпись в рамке ввода Claude, строка состояния Codex, «tab to queue message», уведомление «warnings» у ждущего Codex с текстом) есть тест, и добавлены тесты на произвольную незнакомую строку подвала у каждого агента
- [ ] Когда открыт чат, закрытие любого окна поверх него — просмотра картинки, окна сессий, настроек, расхода, сведений о подключении, палитры, листа фоновых агентов, меню «⋯» — и возврат на вкладку браузера ставят фокус в поле ввода чата (единым правилом фокуса чата, а не поштучно в каждом окне); на устройствах с грубым указателем — тихий фокус без клавиатуры; гость без поля — без изменений
- [ ] Названо по формам транскриптов (без содержимого), как Claude и Codex записывают сообщение человека, поставленное в очередь и доставленное агенту посреди хода (отдельная запись человека, служебная запись очереди, вложение к результату инструмента) — и чего не записывают
- [ ] Такое сообщение стоит в переписке ленты репликой человека на своём месте по времени (служебная обёртка не показывается); на обоих транспортах
- [ ] Локальная запись «в очереди» заменяется этой репликой без дубля; если агент доставленное сообщение не пишет — пометка «в очереди» снимается, когда очередь на экране агента опустела (число очереди стало нулём при узнанном экране), и запись остаётся с пометкой «доставлено»; пометка не висит после конца хода
- [ ] Сообщения человека в чате прижаты к левому краю, как ответы агента: плашка остаётся (отличается фоном), но не уходит вправо; то же для локальных записей («отправляется», «в очереди», «отправлено», «команда отправлена») и их кнопок; прежние тесты, закреплявшие правый край, переписаны под левый
