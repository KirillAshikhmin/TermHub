## Что должно заработать

Терминал в LAN, через relay и из CLI начинает ходить через control mode, сохраняя всё
прежнее поведение. Появляется настройка агента, кадр состояния терминала и флаг у пресета
Codex.

## Критерии приёмки

- [ ] `attachTerminal` внутри использует `session-link`; её внешний контракт сохранён, и
      прежние тесты `bridge.unit.test.ts` проходят без переписывания под новую реализацию
- [ ] `TerminalHandle` расширен снимком экрана и сигналом смены альтернативного экрана;
      relay-путь (`relay-link.ts`) передаёт то и другое так же, как LAN
- [ ] В конфиге агента появляется `terminalMode` со значениями `control` и `attach`;
      отсутствие поля означает `control`; неизвестное значение читается как `control`
      и пишет предупреждение в лог
- [ ] Клиент может попросить прежний способ полем в первом кадре RESIZE; настройка агента
      старше просьбы клиента
- [ ] Выбранный режим сообщается клиенту, чтобы интерфейс мог его показать
- [ ] Новый кадр состояния терминала добавлен в `frames.ts` следующим свободным номером;
      клиент, который его не знает, обязан его пропустить — существующий декодер это уже
      позволяет, добавь тест на пропуск неизвестного кадра
- [ ] Пресет Codex запускается с `--no-alt-screen`; прежние аргументы пресета сохранены
- [ ] `termhub doctor` называет режим подключения терминала
- [ ] Read-only гость по-прежнему не может писать: `send-keys` для него не вызывается
- [ ] Звонок (BEL) продолжает распознаваться; индикатор активности и заголовки сессий не
      изменились
- [ ] `npx vitest run` зелёный целиком, включая `e2e.full.test.ts`; новых падений нет
