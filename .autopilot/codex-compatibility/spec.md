# Спецификация: совместимость TermHub с Codex

## Задача

В веб-терминале активный Codex постоянно перерисовывает TUI и заголовок. Из-за этого
выделение xterm исчезает раньше, чем браузер успевает его скопировать, а `Command+C`
либо не видит выделения, либо уходит в терминал как `Ctrl+C`. Одновременно Codex по
умолчанию пишет в terminal title только индикатор активности и имя проекта, поэтому
TermHub показывает `TermHub` вместо имени потока Codex; заголовок браузерной вкладки
вообще остаётся статическим `TermHub`.

## Решение

TermHub будет сохранять последний непустой снимок выделения, копировать его при
завершении drag-жеста и отдавать его по `Command/Ctrl+C`, даже если перерисовка Codex
уже погасила подсветку. Codex-пресет будет запускаться с неподвижной анимацией title и
с `thread-title` в terminal title. Внутренняя вкладка сессии и вкладка браузера будут
показывать содержательный заголовок, а Codex-состояние `Action Required` станет
распознаваться как ожидание пользователя.

## Что здесь называется именем сессии

- **tmux-id** — технический адрес соединения (`TermHub`), который уже зашит в hash,
  websocket/relay scope и команды управления. Он остаётся стабильным до явного
  переименования пользователем.
- **проект Codex** — имя рабочей папки (`TermHub`); сейчас это единственный текст в
  title по умолчанию, поэтому разные разговоры выглядят одинаково.
- **имя потока Codex** — имя сохранённого разговора (`thread-title`), которое меняет
  `/rename` и которое Codex обновляет через OSC title. Именно оно становится главным
  отображаемым именем вкладки; до появления имени Codex честно отдаёт идентификатор.

Таким образом требование «сама сессия так и называется TermHub» закрывается не
опасной автоматической сменой tmux-id, а заменой папочного display title на имя
реального потока Codex в обоих видимых местах.

## Результаты аудита Codex

1. Codex 0.151 по умолчанию выбирает terminal title `activity + project-name`, а не
   `thread-title`; TermHub не может показать имя, которого нет в `pane_title`.
2. Codex анимирует title с интервалом 100 мс и перерисовывает TUI. В web/xterm это
   делает обычное выделение ненадёжным; одного штатного copy handler xterm мало.
3. Официальный title ожидания Codex — `[ ! ] Action Required` (анимированная скрытая
   фаза `[ . ] ...`). Текущий парсер знает только символы Claude, поэтому ошибочно
   считает Codex обычной неуправляемой сессией и теряет корректный waiting/activity.
4. Заголовок HTML-документа всегда `TermHub` и никак не связан с открытой сессией.
5. Codex уже есть в whitelist пресетов, но запускается голой командой `codex`, без
   настроек title/animation, необходимых именно для браузерного терминала.
6. `pane_current_command` у npm-установки Codex может выглядеть как `node`, поэтому
   бейдж команды не является надёжным способом определить Codex. Исправление не
   строит на нём эвристику.
7. Уже работающий процесс нельзя безопасно перевести на новые startup overrides;
   для него остаётся штатный `/title`, а все новые Codex-сессии из web-пресета сразу
   получают правильный контракт.
8. Multiline-клавиши у Claude и Codex исторически различались (`ESC+CR` против
   надёжного `Ctrl+J` в Codex). Текущий Codex 0.151 принимает настраиваемые keymaps;
   в этом изменении существующий Enter-контракт не меняется без отдельного живого
   воспроизводимого дефекта, чтобы не сломать Claude.

## Решения по реализации

1. **Копирование принадлежит web-терминалу.** Небольшой контроллер хранит последний
   непустой selection snapshot в пределах одного mount. Он слушает selection change,
   начало/конец мышиного жеста и keyboard copy. Почему: xterm знает текст выделения,
   а тип запущенного приложения знать не требуется.
2. **Копирование использует общий clipboard helper.** Так сохраняется fallback для
   небезопасного LAN-origin. Ошибка автокопирования не разрушает выделение и не шлёт
   текст в pty; пользователь может повторить `Command/Ctrl+C`.
3. **Codex-пресет задаёт только process-local overrides:** `tui.animations=false` и
   `tui.terminal_title=["activity","thread-title"]`. Почему: это устраняет известный
   redraw-конфликт и включает имя потока, не переписывая пользовательский
   `~/.codex/config.toml`. Остальные способы запуска Codex остаются без изменений.
4. **Разбор terminal title общий для агента и web.** Помимо прежних Claude-индикаторов,
   он знает два официальных Codex-префикса action-required. Почему: карточка, вкладка,
   activity dot и push не должны расходиться.
5. **Browser title следует активной session-scoped области.** Первым fallback служит
   tmux-имя из маршрута; после list poll терминальный title уточняет его. При уходе на
   несессионный экран title возвращается к `TermHub`.
6. **Никакого чтения внутренней базы Codex.** Имя приходит через публичный OSC title;
   внутренние SQLite/rollout форматы Codex не становятся зависимостью TermHub.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `terminal-copy` | snapshot выделения и решение copy/pass | обработчики selection, gesture end и keyboard copy | исчезновение xterm-selection при redraw, clipboard fallback |
| `session-title` | разбор Claude/Codex pane title и статуса | `titleIndicator`, `sessionManaged`, `sessionWorking`, `sessionWaiting`, `sessionTitleText` | конкретные prefix regex |
| `session-tabs` | актуальная подпись tmux-сессии | обновление DOM и callback текущего display title | poll/cache списка сессий |
| `document-title` | заголовок браузера для текущего route/workspace | установить session title или базовый `TermHub` | нормализацию пустых/повторяющихся значений |
| `session-preset` | безопасная argv-команда каждого whitelist-пресета | argv для `tmux new-session` | Codex process-local overrides |

Швы тестирования: чистое решение `terminal-copy`, общий `session-title`, argv
`session-preset` и callback `session-tabs`; browser title проверяется через workspace/
router harness. Новых сетевых или серверных контрактов нет.

## Вне рамок

- Автоматическое переименование самого tmux-сеанса по названию потока Codex: это
  разрушило бы стабильные URL, relay scope и открытые вкладки; R06/R09 требуют
  отображаемый title, а не смену транспортного идентификатора.
- Правка глобального `~/.codex/config.toml`: пользовательские настройки не принадлежат
  TermHub. Уже запущенная сессия применяет `/title`; новые web-presets получают override.
- Реализация мышиного selection внутри самого Codex TUI: TermHub чинит свой web/xterm
  слой и параметры запуска, не форкает Codex.
